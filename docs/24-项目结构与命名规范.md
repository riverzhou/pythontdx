## 一、五层模型：先看这一张图

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 外壳层   src/main · src/preload · src/web                           │
│ 窗口/托盘/更新/文件对话框/本地服务拉起；渲染层加载方式因端而异      │
└───────────────────────────┬─────────────────────────────────────────┘
                            │ 只有两条通道：window.desktop（壳能力）
                            │              HTTP /api + /ws（数据）
┌───────────────────────────▼─────────────────────────────────────────┐
│ 渲染层   src/renderer（桌面与 Web 共用同一份）                      │
│ components 画界面 · stores 管状态 · lib 管传输与纯工具              │
└───────────────────────────┬─────────────────────────────────────────┘
                            │ 只经 @shared 契约
┌───────────────────────────▼─────────────────────────────────────────┐
│ 契约层   src/shared                                                 │
│ 类型、契约与纯函数；禁 electron / node:* / DOM，两端 tsconfig 都编  │
└───────────────────────────┬─────────────────────────────────────────┘
                            │ HTTP + WebSocket（唯一数据面）
┌───────────────────────────▼─────────────────────────────────────────┐
│ 数据后端 python/                                                    │
│ 通达信协议、行情调度与缓存、离线同步、数据湖；数据逻辑唯一实现      │
└─────────────────────────────────────────────────────────────────────┘

横切：scripts/（工具链）   docs/（知识）   .github/（CI）
```

| 层       | 只做                                    | 绝不做                                        |
| -------- | --------------------------------------- | --------------------------------------------- |
| 外壳     | 装配窗口、壳 IPC、拉起/守护 Python 服务 | 解析行情、缓存、合并、业务判断                |
| 渲染层   | 展示、交互、传输调度                    | 直接 `fetch`、直接读 `window.desktop`、算行情 |
| 契约层   | 描述数据结构与调用签名、放纯函数        | 引入任何平台 API、持有状态                    |
| 数据后端 | 协议、IO、缓存、统计、数据湖            | 关心界面布局与图标                            |
| 工具链   | 构建、签名、截图、探针、数据自检        | 被运行时 import                               |

**为什么值得守**：桌面与 Web 共用渲染层，任何平台代码漏进 `shared` 都会让其中一端编译失败；
数据逻辑漏回 TS，就会出现「桌面一套缓存、Web 一套缓存」的双份实现（1.5.0 之前的老问题）。

├─ .github/workflows/  check（质量门禁）/ build-windows / build-macos / release / release-windows-zip
├─ out/  release/  screenshots/  .tmp/    构建与验收产物，全部 gitignore

根目录**只允许**放：工程配置、对外门面文档（README/AGENTS/PRINCIPLES/PLAN/CHANGELOG）、

## 三、逐层说明

### 3.1 `src/main/` —— 入口 + services

```text
src/main/
├─ index.ts            组合根：读配置、拉起 sidecar、建窗口/托盘、注册 IPC、生命周期
└─ services/           其余全部能力，一个文件一类职责
   ├─ server.ts        拉起 / 守护 python/dist/tdx-bridge --serve
   ├─ store.ts         本机配置读写（userData/pythontdx.json）+ 窗口状态
   ├─ window.ts        主窗口创建、尺寸记忆、显示/隐藏
   ├─ tray.ts          托盘菜单
   ├─ native-ipc.ts    ipcMain 处理器：窗口/状态/对话框/通知/外链
   ├─ capture.ts       截图工具的主进程侧（npm run shot）
   ├─ diagnostics.ts   渲染层日志与崩溃转发到终端
   ├─ legacy.ts        旧数据目录迁移（有单测）
   └─ linux-desktop.ts .desktop 集成（有单测）
```

判据只有一条：**`index.ts` 负责「装配」，其余逻辑进 `services/`。**
不要在主进程里写行情 IO —— 那是 Python 的职责（`PRINCIPLES.md` A2）。

### 3.2 `src/preload/`

`index.ts` 暴露 `window.desktop`；`index.d.ts` 是给渲染层的类型声明。
新增壳能力时三处同步：`preload/index.ts` 实现 → `shared/desktop.ts` 契约 →
`main/services/native-ipc.ts` 处理器。白名单之外一律不暴露。

### 3.3 `src/shared/` —— 契约与纯函数

```text
src/shared/
├─ api.ts              数据面契约（PythonTdxApi，方法名与 /api 路由一一对应）
├─ desktop.ts          壳能力契约（window.desktop 的形状）
├─ types.ts → types/    共享数据类型门面（market/mac/f10/data/app/shell/push）
├─ market.ts  format.ts  limits.ts  ranking.ts  watchlist.ts  portfolio.ts
├─ indicators.ts  ma.ts  formula.ts(+formula-engine.ts)  drawing.ts  patterns.ts
├─ csv.ts  archive.ts  alerts.ts  distribution.ts  trades.ts  search.ts  window.ts
├─ markdown.ts  version.ts
├─ f10.ts → f10/       F10 页面模型的对外门面与实现
└─ *.test.ts           与源文件同名的纯函数测试
```

**门面约定**（项目里已成型，继续沿用）：

| 写法                   | 何时用                           | 例                                                  |
| ---------------------- | -------------------------------- | --------------------------------------------------- |
| `x.ts` + `x/` 目录     | 内部实现要按子域拆成多文件       | `f10.ts` 门面 + `f10/{parse,model,tables,links}.ts` |
| `x.ts` + `x-engine.ts` | 内部只有一块重实现，不值得建目录 | `formula.ts` 门面 + `formula-engine.ts`             |

两种都可以，**但对外只认门面**：外部一律 `import … from '@shared/f10'`，不直接引实现文件。

`src/shared/**` 的硬约束（`AGENTS.md` 硬规则 2）：禁止 `electron` / `node:*` / DOM。
它同时被 `tsconfig.node.json` 与 `tsconfig.web.json` 编译，引入平台代码必有一侧失败。
推论：**需要 Node API 的测试不能放这里**，放 `scripts/<类别>/*.test.mjs`（见 3.7）。

### 3.4 `src/renderer/` —— 一套界面两端用

```text
src/renderer/
├─ index.html
└─ src/
   ├─ main.tsx         入口：按顺序 import 全部样式，再挂载 App
   ├─ App.tsx          应用外壳：三栏布局、主区视图路由、快捷键、布局拖拽
   ├─ components/
   │  ├─ panels/       19 个 *Panel：主工作区标签页 / 弹窗级页面
   │  ├─ charts/       5 个图表：KLineChart / TrendChart / IndicatorSubchart / ChartSkeleton / Sparkline
   │  ├─ chrome/       6 个壳件：TitleBar / Sidebar / StatusBar / Menu / WorkspaceTabs / SearchBox
   │  └─ atoms/        17 个原子件：Icons / OrderBook / QuoteHeader / TradeTape …（含 1 个测试）
   ├─ lib/             传输与纯工具（14 个模块 + 7 个测试）
   ├─ stores/          全局状态（9 个模块 + 2 个测试）
   └─ styles/
      ├─ tokens.css    设计令牌
      ├─ base.css      重置与排版
      ├─ components.css 通用小件（卡片/按钮/标签/分段/骨架/开关…）
      ├─ panels/       6 份业务面板样式（market / f10 / tools / settings / reports / shell）
      └─ layout/       3 份骨架样式（shell / workspace / tuning）
```

**`components/` 按用途分四层**；命名仍表达层次（`*Panel` 是页面，其余是部件）：

| 命名                  | 含义                                      | 例                                                            |
| --------------------- | ----------------------------------------- | ------------------------------------------------------------- |
| `*Panel.tsx`（19 个） | 主工作区标签页 / 弹窗级页面，自带数据加载 | `DataPanel` `RankingPanel` `F10Panel`                         |
| `*Chart*`             | 画布/图表渲染（SVG 为主）                 | `KLineChart` `TrendChart` `IndicatorSubchart` `ChartSkeleton` |
| 壳件                  | 应用框架，不属于业务内容                  | `TitleBar` `Sidebar` `StatusBar` `Menu` `WorkspaceTabs`       |
| 名词部件              | 可复用内容块                              | `OrderBook` `QuoteHeader` `StatsGrid` `Sparkline`             |
| 基础设施              | 全应用共用的小件                          | `Icons` `EmptyState` `MarkdownView` `ChartSkeleton`           |

目录与命名的对应关系：`panels/` ↔ `*Panel`、`charts/` ↔ 图表、`chrome/` ↔ 应用骨架、
`atoms/` ↔ 其余可复用件。新组件先判断属于哪层，再放进去；`Icons` 是图标总表，被 30 处引用。

`lib/` 的职责边界：

| 文件                                                                                                           | 管什么                                                          |
| -------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `client.ts`                                                                                                    | **唯一出口**：导出 `api`（数据）+ `shell`（壳）+ `errorMessage` |
| `http-api.ts`                                                                                                  | 数据面唯一实现：`/api/*` 与 `/ws`，两端共用                     |
| `shell.ts`                                                                                                     | 壳能力：桌面走 `window.desktop`，浏览器降级                     |
| `push.ts`                                                                                                      | 面板级推送订阅（`/api/push`）                                   |
| `realtime.ts`                                                                                                  | 刷新节奏、最后一根 K 线合成                                     |
| `chart-geometry.ts`                                                                                            | 图表几何纯函数（可测）                                          |
| `tone.ts`                                                                                                      | 红涨绿跌语义色                                                  |
| `dom.ts` `download.ts` `chart-keys.ts` `board-categories.ts` `breadth.ts` `trend-cache.ts` `legacy-storage.ts` | 各自单一职责                                                    |

组件不直接 `fetch`、不直接读 `window.desktop`：调用点收敛在 `lib/client.ts` 与 `stores/**`。

### 3.5 `src/web/`

只有三件套：`index.html`、`main.tsx`（挂载共享渲染层）、`env.d.ts`。
**这里不许出现行情适配器、第二套组件或第二套状态**；差异只允许在入口与传输。

### 3.6 `python/` —— 协议层成包，其余平铺

`python/` 根目录按「数据集 / 服务」拆模块（34 个），协议层单独成包 `tdxproto/`（9 个模块）。
`tdx_bridge.py` 仍是 `Bridge` 编排与门面的所在（5753 行），但只负责「用协议层做业务」，
不再同时承载常量、编解码、连接与解析。`tests/`、`fixtures/` 各占一个子目录。

**为什么协议层要拆**：`tdx_bridge.py` 曾到 9364 行、148 个顶层符号，改一个字段要在近万行里
找上下文。拆分沿线切，依赖单向（左边的依赖右边的）：

```text
base → codec → session
base → constants → cache
base → codec → blocks → parsers
base / constants / cache → requests
blocks / constants / requests / session → business
以上全部 → tdx_bridge.py（Bridge 编排 + 备份 + JSONL）
```

`base` 只放最共享的 7 个符号（`TdxError`、`pythontdx_data_dir`、`full_code`、`parse_code`、
`code_bytes`、`MARKET_IDS/NAMES`），其余模块都依赖它，它不依赖本包任何模块。

**门面**：`tdx_bridge.py` 把 `tdxproto/*` 的全部名字再导出——`import tdx_bridge`、
测试里的 `mock.patch.object(tdx_bridge, "parse_bars")`、`Bridge` 内部的裸名调用都继续有效。

| 组           | 模块                                                                                                                                                                                                                                                                                                                                                                                         | 共同点                                   |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| 协议与传输   | `tdx_bridge.py`（5753 行，门面 + Bridge）`tdxproto/`（9 个模块）`tdx_mac.py` `tdx_mac_ext.py` `tdx_local.py` `tdx_f10.py` `server_catalog.py` `trading_calendar.py`                                                                                                                                                                                                                                                                | `tdx_*` = 通达信通道；只谈字节与端口     |
| 服务面       | `tdx_server.py` `subscription_hub.py` `push_manager.py`                                                                                                                                                                                                                                                                                                                                      | 对外 HTTP/WS，进程内扇出                 |
| 数据湖与任务 | `data_paths.py` `data_coverage.py` `data_integrity.py` `duckdb_query.py` `offline_sync.py` `parquet_store.py` `parquet_export.py` `kline_export.py` `kline_manifest.py` `snapshot_archive.py` `tick_archive.py` `auction_archive.py` `code_archive.py` `delisted_archive.py` `flow_archive.py` `protocol_archive.py` `finance_history.py` `adjust_factors.py` `f10_pit.py` `local_import.py` | 一个数据集一个归档器，Parquet + manifest |
| 领域计算     | `formula.py` `patterns.py` `gbbq.py`                                                                                                                                                                                                                                                                                                                                                         | 纯函数，可单测                           |
| 入口与构建   | `tdx_server.py`（入口）`build.py` `connect.cfg` `requirements-data.txt` `fixtures/`（22 份报文与快照）                                                                                                                                                                                                                                                                                       | 不参与业务逻辑                           |

```text
python/
├─ tdx_server.py          唯一入口：HTTP/WS 门面 + 静态页面托管
├─ tdx_bridge.py          门面 + Bridge 编排（再导出 tdxproto 的全部名字）
├─ tdxproto/              协议层（base/constants/cache/codec/session/requests/parsers/blocks/business）
├─ …（其余 32 个模块，见上表）
├─ tests/                 34 个 test_*.py + __init__.py（包标记，让 discovery 递归）
├─ fixtures/              真实报文 / 节假日快照，测试只读
├─ build.py               Nuitka 打包（产物 python/dist/tdx-bridge；源码指纹递归 *.py）
└─ connect.cfg            客户端内置主站列表（随包分发）
```

### 3.7 `scripts/` —— 一个入口 + 四类工具

```text
scripts/
├─ python.mjs       Python 命令唯一入口：选解释器、给中文报错
├─ build/           打包：generate-icon / before-pack(+test) / sign-win / build-win-zip / version.test
├─ dev/             验收素材：screenshot / web-shot / social-preview
├─ data/            数据运维：data_audit / archive-snapshot
├─ probe/           一次性协议探针：probe-tdx / probe_0547 / analyze_0547

```

判据：**产物进安装包或发布页 → `build/`；本机看一眼图 → `dev/`；动用户数据 → `data/`；
只为取证、不进流程 → `probe/`。**

### 3.8 `docs/` —— 编号正文 + 三个分区

```text
docs/
├─ README.md          文档入口：按「什么时候读」分类的索引
├─ 00 … 24-*.md       编号正文
├─ releases/          逐版本发布说明（文件名 = 版本号）+ README + 编年史.md
├─ history/           项目起点等史料（只读）
└─ assets/            README / 发布说明用的截图（25 张，17MB）
```

编号规则见 [`docs/README.md`](README.md)：**编号是稳定 ID，只增不改**；
标题统一 `NN · 名称`；分类靠索引，不靠重排。

## 四、命名规范

### 4.1 总表

| 对象        | 规则                                                            | 正例                                | 反例 / 说明                                       |
| ----------- | --------------------------------------------------------------- | ----------------------------------- | ------------------------------------------------- |
| 目录        | 小写；领域名，不加版本号                                        | `components` `stores` `releases`    | ~~`v2/`~~ ~~`new/`~~                              |
| TS 模块     | kebab-case                                                      | `chart-geometry.ts` `http-api.ts`   | ~~`chartGeometry.ts`~~                            |
| 组件        | PascalCase；后缀表达层次（见 3.4）                              | `RankingPanel.tsx` `KLineChart.tsx` | 无后缀的业务组件要能一眼看出是部件                |
| 测试        | 与被测文件同名，同目录                                          | `market.test.ts` 对 `market.ts`     | 曾用名 `defaults.test.ts` 测的是 `types.ts`，已改 |
| Python 模块 | snake_case                                                      | `snapshot_archive.py`               |                                                   |
| Python 测试 | `test_<被测模块>.py`；跨模块回归包 `test_<主题>_regressions.py` | `test_snapshot_archive.py`          | ~~`test_p0_fixes.py`~~（里程碑命名，已改）        |
| 脚本        | 动词-对象                                                       | `build-win-zip.ps1` `probe-tdx.mjs` | ~~`helper.py`~~                                   |
| 文档        | `NN-中文名.md`，标题 `NN · 名称`                                | `24-项目结构与命名规范.md`          | 标题缺编号或错号（曾出现 `13 · eltdx…` 实为 14）  |
| 常量 / 类型 | `SCREAMING_SNAKE` / `PascalCase`                                | `DEFAULT_SETTINGS` `QuoteSnapshot`  |                                                   |

### 4.2 四条容易越界的补充规则

1. **目录是领域，文件是角色。** 「行情墙」是领域，「Panel / store / lib」是角色；
   别把两个都塞进文件名（`MarketListPanel` 可以，`MarketListPanelComponent` 不行）。
2. **缩写必须在文件头解释一次。** 行业术语（`gbbq` 股本变迁、`zhb` 涨跌家数）保留，
   但文件开头的 docstring 第一行要写人话，不能只有缩写。
3. **禁止垃圾桶文件**：`utils.ts` / `helpers.ts` / `common.ts` / `misc.py`。
   找不到合适归属，说明职责还没想清楚——先想清楚再落盘。
4. **不拿状态词做名字**：`v2`、`new`、`final`、`old`、`tmp`、日期后缀。
   版本信息放 `CHANGELOG` / `releases/`，不放进文件名。
