# 23 · 前后端边界与双端一致性

> 适用版本：pythontdx 1.5.0+
>
> 这份文档回答三个问题：
>
> 1. 前端 TypeScript 与后端 Python 各自能做什么、不能做什么；
> 2. 同一条能力在 Electron 与 Web 上分别走哪条路，为什么它们是同一份逻辑；
> 3. 改代码/发版前，怎么证明两端没有漂移。
>
> 强制规则见 `PRINCIPLES.md` 的 **A2**（数据逻辑归 Python，TS 只负责展示与传输）
> 与 **A8**（Web 与 Electron 同源）。本文是它们的落地说明，不是另一套原则。

---

## 一、一句话边界

**Python 产生数据，TypeScript 画数据。**

- Python：协议、解析、行情编排、缓存、TTL/时段策略、K 线增量合并、统计聚合、
  落盘、数据任务、全市场分页扫描的**状态与计数**。
- TypeScript：组件、交互、UI 状态、格式化、图表几何、传输适配（IPC/HTTP/SSE/WS）、
  壳生命周期（窗口/托盘/更新）、**何时调用 Python** 的定时器与队列。

判断一段代码放哪层，只问一句：

> 把这段代码搬到另一端，会不会得到不同的行情数字？
>
> 会 → 必须放 Python；不会（只影响样子/时机/传输方式）→ 可以放 TS。

---

## 二、分层与依赖方向

```text
┌──────────────────────────────┐   ┌──────────────────────────────┐
│ Electron 渲染层               │   │ Web 渲染层                    │
│ src/renderer                  │   │ src/renderer（同一份）         │
└──────────────┬───────────────┘   └──────────────┬───────────────┘
               │ window.api                        │ window.api
               ▼                                   ▼
┌──────────────────────────────┐   ┌──────────────────────────────┐
│ preload + Electron main       │   │ src/web/http-api              │
│ IPC 转发、壳生命周期           │   │ fetch / SSE / WebSocket       │
└──────────────┬───────────────┘   └──────────────┬───────────────┘
               │ JSON Lines (stdin/stdout)         │ HTTP / WS
               ▼                                   ▼
        ┌────────────────────────────────────────────────┐
        │ python/tdx_bridge.py · Bridge                  │
        │ 协议 / 解析 / 编排 / 缓存 / K 线增量 / 统计     │
        └──────────────────┬─────────────────────────────┘
                           │ TCP 7709 / MAC / HTTP 7615 / 文件
                           ▼
                  通达信主站 / 计算服务器
```

两条传输最终调用 **同一个 `Bridge` 实例/同一批方法**：

- 桌面：`src/main/services/tdx/index.ts` → `TdxBridge.send(cmd)` → Python `dispatch`
- Web：`src/web/http-api.ts` → `tdx_server.py` 路由 → 同一个 `Bridge`

因此「两端一致性」不是靠两边各写一遍再对齐，而是靠**只有一份数据实现**。

## 三、职责矩阵

| 能力 | 唯一实现 | TypeScript 侧只做 |
| --- | --- | --- |
| 7709/MAC/7615 帧与字段解析 | `python/tdx_bridge.py`、`tdx_f10.py` | 无 |
| 实时行情编排（快照→增量→合并→竞价→MAC 兜底） | `Bridge.live_quotes` | 去重、取消检查、超时、转发 |
| 行情缓存 / 游标 | `Bridge.quote_cache` / `quote_cursors` | 不缓存、不合并 |
| 分时 10s / 五日 60s / K 线 60s TTL | `Bridge.minute_cached` / `five_day_cached` / `kline_cached` | 只传 `fresh` 标志 |
| 实时 K 线（首帧全量、tail 20 根、60s 补全量、断层重取） | `Bridge.kline_live` | 只传 `first` 标志 |
| 涨跌家数扫描/分页/计数/TTL/跨日失效 | `Bridge.breadth_begin` / `breadth_step` / `_breadth_counts` | 驱动 `begin/step` 循环（为了页间插队） |
| 成交明细 / 竞价 / 资金流 | `Bridge.trades` / `auctions` / `money_flow` | 按订阅节奏调用 |
| F10 目录/正文/在线页签 | `Bridge.f10_*` | 渲染 |
| 离线数据任务/数据湖 | `python/offline_sync.py` 等 | 展示进度 |
| 代码表与拼音搜索索引 | Python 提供 `code_list`；TS 建展示索引 | 本地搜索、排序、高亮 |
| 交易时段显示 | `src/shared/market.ts`（纯展示） | 标题栏/状态栏显示 |
| 轮询/推送间隔 | Python 决定数据 TTL；壳决定何时调用 | 定时器、退避、窗口可见性 |
| 涨跌色/格式化/图表几何 | `src/shared/format.ts`、`tone.ts`、`chart-geometry.ts` | 纯展示 |

**允许留在 TS 的“逻辑”**只有三类：

1. **纯展示计算**：格式化、坐标、指标显示、排序/过滤的视图层结果；
2. **传输控制**：超时、取消、重试退避、并发合并、窗口可见性；
3. **UI 状态**：选中代码、面板开关、自选分组、主题、布局。

## 四、同一条能力的两条路（当前映射）

| 能力 | Python 命令/方法 | Electron | Web |
| --- | --- | --- | --- |
| 实时行情 | `live_quotes` | `QuotePoller` → `TdxBridge.send('live_quotes')` | `POST /api/quotes`；SSE `/api/stream`；WS `/ws` |
| 行情订阅调度 | `SubscriptionHub`（Web）/`QuotePoller`（桌面，传输） | 主进程定时器，间隔用 `pollDelayMs()` | 浏览器定时器/SSE/WS；间隔用 `pollDelayMs()` |
| 日/周/月 K | `kline_cached` | `fetchKline` → `kline_cached` | `GET /api/kline` |
| 实时 K 线 | `kline_live` | `fetchKlineLive` → `kline_live` | `POST /api/kline_live` |
| 分时 | `minute_cached` / `minute` | `fetchMinuteTrend(fresh)` | `GET /api/minute?fresh=0/1` |
| 五日 | `five_day_cached` / `five_day` | `fetchFiveDayTrend(fresh)` | `GET /api/five_day?fresh=0/1` |
| 涨跌家数 | `breadth_begin` / `breadth_step` | `fetchMarketBreadth` 循环 | `POST /api/market_breadth`（服务端循环） |
| 逐笔 | `trades` | `fetchTrades` | `POST /api/trades` |
| 分类行情 | `category_quotes` | `fetchCategoryQuotes` | `POST /api/category` |
| F10 | `f10_*` | `fetchF10*` | `POST /api/f10_*` |
| 离线同步 | `offline_sync_*` | `bridge.send` | `POST /api/offline_sync_*` |
| 应用配置 | — | 主进程 `AppStore` | `localStorage`（UI 状态） |

> 桌面与 Web 的**应用状态**持久化不同（文件 vs localStorage），这是外壳差异，
> 不属于行情数据；两侧字段都来自 `src/shared/types.ts` 的 `AppState`。

## 五、缓存与刷新规则（唯一来源）

| 数据 | 位置 | TTL/窗口 | 说明 |
| --- | --- | --- | --- |
| 实时报价 | `Bridge.live_quotes` + 游标 | 每次调用 | 快照覆盖价格，增量保留五档 |
| 分时 | `Bridge._minute_cache` | 10s | 推送传 `fresh=true` 绕过 |
| 五日 | `Bridge._five_day_cache` | 60s | 推送传 `fresh=true` 绕过 |
| K 线 | `Bridge._kline_cache` | 60s | 首屏 `cacheOnly` 读本地 parquet |
| 实时 K 线 | `Bridge._kline_live_cache` | tail 20 根；60s 补全量 | 断层自动重取全量；tail 不落盘 |
| 涨跌家数 | `Bridge._breadth_cache` | 交易 15s / 午休 120s / 收盘 300s | 跨北京时间日期失效 |
| 行情非交易时段 | `pollDelayMs()` / `_quote_interval()` | 10 倍、最少 30s | 两侧测试锁住同一组向量 |

**禁止**在 TS 里再出现用于**业务决策**的行情缓存、TTL、`limitUp` 统计、
全量/断层判断。渲染层唯一允许的“合并”是把 Python 推来的 tail 追加进图表的
只读展示缓冲（否则每秒重传 800 根不可接受）；它必须与 Python `merge_kline_bars`
使用同一组测试向量，且不能用于缓存失效或指标计算。

需要新增缓存时，先加 Python 方法 + 测试，再让两个适配器转发。

## 六、一致性怎么保证

### 6.1 编译期

- `src/shared/ipc.ts` 的 `PythonTdxApi` 是两端共同实现的接口；
  少实现一个方法、参数类型不一致，`npm run typecheck` 直接失败。
- `src/shared/types.ts` 是字段契约；Python 返回的字段由 Python 测试锁住。

### 6.2 测试期

- Python：`test_tdx.py` 覆盖缓存/TTL/K 线增量/涨跌家数；`test_server.py` 覆盖
  HTTP 路由与 `fresh` 透传；`test_live_quotes.py` 覆盖行情合并顺序。
- TypeScript：`market.test.ts` 覆盖 `pollDelayMs`/时段边界；`poller.test.ts`
  覆盖取消后不再空转；`push.test.ts` 覆盖面板订阅生命周期。
- 同一组时段/TTL 向量必须同时出现在 Python 与 TS 测试里（当前：交易/竞价、
  午休、收盘、周末、临近边界不足 500ms）。

### 6.3 发布前人工核对

> 2026-11-06 1.5.0 实测：桌面 `v1.5.0` 与 Web `v1.5.0-web` 同时显示
> `sh000001` 3647.90、涨 911/跌 4548，分时/盘口/逐笔一致；截图见
> `docs/assets/pythontdx-1.5-overview.png` 与 `docs/assets/pythontdx-1.5-web.png`。

- [ ] 新增/修改的能力在第四节映射表里能找到两端入口；
- [ ] 两端参数名/默认值/错误语义一致；
- [ ] 没有新增 TS 行情缓存/合并/统计；
- [ ] `npm run check` 全绿；
- [ ] Web 与 Electron 各截一张关键界面，数字/涨跌色/时间一致；
- [ ] 更新 `CHANGELOG.md` 与 `docs/07` 的验证记录。

## 七、当前已知边界（不是“原则允许”，是待还的技术债）

| 边界 | 影响 | 计划 |
| --- | --- | --- |
| 桌面与 Web 各自启动一个 Python 进程 | 同机同时运行时会有两条 7709 连接与两份内存缓存 | 长期改为单后端 + 桌面连 HTTP；见 `PLAN.md` 技术债 |
| 桌面行情定时器在主进程、Web 在浏览器/Python Hub | 调度实现有三处，但只负责“何时调用”；数据规则仍在 Python | 保持薄壳；新增调度只复用 `pollDelayMs`/`_quote_interval` 测试向量 |
| 渲染层保留 K 线展示缓冲并合并 tail | 只影响绘制；权威缓存仍在 Python | 合并规则与 Python 共用测试向量，禁止扩散为业务缓存 |
| 搜索索引在 TS 本地构建 | 只影响搜索体验，不影响行情 | 可接受；代码表源头仍是 Python |
| Web UI 状态在 localStorage | 多浏览器/多设备不同步 | 属于 UI 状态，非行情；后续可接后端配置 |
| 节假日不精确 | 工作日节假日仍按交易时段轮询 | 需引入交易日历；见 `PLAN.md` |

## 八、反模式清单

| 不要 | 应该 |
| --- | --- |
| Web 端自己决定 K 线尾部窗口/缓存/TTL/断层 | 调 Python `kline_live`，只把 tail 合进展示缓冲 |
| 桌面主进程缓存分时/K 线并设 TTL | Python `minute_cached` / `kline_cached` |
| 两端各写一个涨跌家数扫描/缓存 | Python `breadth_begin/step` |
| 在渲染层 `setInterval(fetch)` | `subscribePush` + 壳调度 |
| 组件直接读 `window.api` / `fetch` | `lib/ipc.ts` + `stores/**` |
| 某端“先补一个兜底”，另一端没补 | 修 Python 或传输层，两端同时生效 |
| 只改一端路由/参数 | 按第四节映射表同时改两端 + 测试 |
