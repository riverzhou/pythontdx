# 23 · 前后端边界与双端一致性

> 适用版本：pythontdx 1.7.0+（2026-11-14 统一传输）
>
> 这份文档回答三个问题：
>
> 1. 前端 TypeScript 与后端 Python 各自能做什么、不能做什么；
> 2. 同一条能力在 Electron 与 Web 上分别走哪条路，为什么它们是同一份逻辑；
> 3. 改代码/发版前，怎么证明两端没有漂移。
>
> 强制规则见 `PRINCIPLES.md` 的 **A2**（数据逻辑归 Python，TS 只负责展示与传输）
> 与 **A8**（Web 与 Electron 同源）。本文是它们的落地说明，不是另一套原则。

---

## 一、一句话边界

**Python 产生数据，TypeScript 画数据；两种外壳走同一条数据通道。**

- Python：协议、解析、行情编排、缓存、TTL/时段策略、K 线增量合并、统计聚合、
  落盘、数据任务、全市场分页扫描的**状态与计数**；
- TypeScript：组件、交互、UI 状态、格式化、图表几何、传输适配（HTTP/SSE/WS）、
  壳生命周期（窗口/托盘/更新）、**何时调用 Python** 的定时器与队列。

**部署模式二选一**：桌面 Electron 与 Web 是两种使用方式，产品设计上**不同时使用**。
同一台机器只允许一个 Python 后端持有 7709 连接；不要为「双开」设计共享缓存或双后端协调。

判断一段代码放哪层，只问一句：

> 把这段代码搬到另一端，会不会得到不同的行情数字？
>
> 会 → 必须放 Python；不会（只影响样子/时机/传输方式）→ 可以放 TS。

## 二、分层与统一拓扑

```text
┌──────────────────────────────┐   ┌──────────────────────────────┐
│ Electron 渲染层               │   │ 浏览器                        │
│ 同一份 src/renderer           │   │ 同一份 src/renderer           │
│ window.desktop（仅壳能力）     │   │ 无 window.desktop             │
└──────────────┬───────────────┘   └──────────────┬───────────────┘
               │                                  │
               │  同一套 HTTP /api + WebSocket /ws │
               └────────────────┬─────────────────┘
                                ▼
                 ┌────────────────────────────────┐
                 │ python/tdx_server.py            │
                 │ 静态页面 + /api + /ws + Bridge  │
                 └────────────────┬───────────────┘
                                  │ TCP 7709 / MAC / HTTP 7615 / 文件
                                  ▼
                         通达信主站 / 计算服务器
```

- **Electron 不再使用 stdio/IPC 行情通道**：主进程拉起本地服务，窗口直接加载
  `http://127.0.0.1:<port>`；开发模式加载 Vite 页面，由 Vite 的 `/api`、`/ws`
  代理到 8765。
- **preload 只暴露 `window.desktop`**：窗口控制、本机状态文件、文件对话框、
  系统通知、Linux 桌面集成；不暴露任何行情方法。
- **渲染层只有一份数据适配器**：`src/renderer/src/lib/http-api.ts`，两端共用。
- 因此「两端一致性」不是靠两边各写一遍再对齐，而是靠**只有一份传输实现**。

> 参考 QuantV5：它的 Electron 主进程只负责拉起 HTTP 服务、加载同一个页面，
> preload 仅窗口控制/文件对话框，数据全部走 HTTP。pythontdx 1.7 采用同一拓扑。
> 唯一保留的壳差异是 UI 状态：桌面写在 `userData/pythontdx.json`，Web 写
> `localStorage`；它们不是行情数据，见第七节。

## 三、职责矩阵

| 能力                                                    | 唯一实现                                                    | TypeScript 侧只做                      |
| ------------------------------------------------------- | ----------------------------------------------------------- | -------------------------------------- |
| 7709/MAC/7615 帧与字段解析                              | `python/tdx_bridge.py`、`tdx_f10.py`                        | 无                                     |
| 实时行情编排（快照→增量→合并→竞价→MAC 兜底）            | `Bridge.live_quotes`                                        | 去重、取消检查、超时、转发             |
| 行情缓存 / 游标                                         | `Bridge.quote_cache` / `quote_cursors`                      | 不缓存、不合并                         |
| 分时 10s / 五日 60s / K 线 60s TTL                      | `Bridge.minute_cached` / `five_day_cached` / `kline_cached` | 只传 `fresh` 标志                      |
| 实时 K 线（首帧全量、tail 20 根、60s 补全量、断层重取） | `Bridge.kline_live`                                         | 只传 `first` 标志                      |
| 涨跌家数扫描/分页/计数/TTL/跨日失效                     | `Bridge.breadth_begin` / `breadth_step` / `_breadth_counts` | 驱动 `begin/step` 循环（为了页间插队） |
| 成交明细 / 竞价 / 资金流                                | `Bridge.trades` / `auctions` / `money_flow`                 | 按订阅节奏调用                         |
| F10 目录/正文/在线页签                                  | `Bridge.f10_*`                                              | 渲染                                   |
| 离线数据任务/数据湖                                     | `python/offline_sync.py` 等                                 | 展示进度                               |
| 代码表与拼音搜索索引                                    | Python 提供 `code_list`；TS 建展示索引                      | 本地搜索、排序、高亮                   |
| 交易时段显示                                            | `src/shared/market.ts`（纯展示）                            | 标题栏/状态栏显示                      |
| 轮询/推送间隔                                           | Python 决定数据 TTL；壳决定何时调用                         | 定时器、退避、窗口可见性               |
| 涨跌色/格式化/图表几何                                  | `src/shared/format.ts`、`tone.ts`、`chart-geometry.ts`      | 纯展示                                 |
| 窗口/文件对话框/通知                                    | Electron 主进程                                             | `window.desktop` 调用                  |

**允许留在 TS 的“逻辑”**只有三类：

1. **纯展示计算**：格式化、坐标、指标显示、排序/过滤的视图层结果；
2. **传输控制**：超时、取消、重试退避、并发合并、窗口可见性；
3. **UI 状态**：选中代码、面板开关、自选分组、主题、标签页布局。

## 四、同一条能力只有一条路

| 能力              | Python 命令/方法                       | 两端共同入口                                              |
| ----------------- | -------------------------------------- | --------------------------------------------------------- |
| 实时行情          | `live_quotes`                          | `POST /api/quotes`；SSE `/api/stream`；WS `/ws`           |
| 行情订阅调度      | `SubscriptionHub`                      | 服务端统一调度；渲染层只声明代码集合与间隔                |
| 日/周/月 K        | `kline_cached`                         | `GET /api/kline`                                          |
| 实时 K 线         | `kline_live`                           | `POST /api/kline_live`                                    |
| 分时              | `minute_cached` / `minute`             | `GET /api/minute?fresh=0/1`                               |
| 五日              | `five_day_cached` / `five_day`         | `GET /api/five_day?fresh=0/1`                             |
| 涨跌家数          | `breadth_begin` / `breadth_step`       | `POST /api/market_breadth`                                |
| 逐笔              | `trades`                               | `POST /api/trades`                                        |
| 交易日历          | `market_status`（TDX 节假日 + 0x120F） | `POST /api/market_status`                                 |
| 分类行情          | `category_quotes`                      | `POST /api/category`                                      |
| F10               | `f10_*`                                | `POST /api/f10_*`                                         |
| 离线同步          | `offline_sync_*`                       | `POST /api/offline_sync_*`                                |
| 备份/恢复         | `backup_*`                             | `POST /api/backup_*`；路径由 `window.desktop.dialogs` 选  |
| 面板级推送        | `PushManager`                          | `POST /api/push_subscribe` + `GET /api/push?client=…` SSE |
| 备份/恢复进度     | `publish_progress`                     | `GET /api/progress` SSE                                   |
| 行情主站测速/切换 | `server_speed_test` / `select_server`  | `POST /api/server_*`                                      |
| 应用状态          | —                                      | 桌面 `window.desktop.state`；Web `localStorage`（壳差异） |

> 桌面与 Web 的**应用状态**持久化不同（文件 vs localStorage），这是外壳差异，
> 不属于行情数据；两侧字段都来自 `src/shared/types.ts` 的 `AppState`。

## 五、缓存与刷新规则（唯一来源）

| 数据           | 位置                                                 | TTL/窗口                         | 说明                                   |
| -------------- | ---------------------------------------------------- | -------------------------------- | -------------------------------------- |
| 实时报价       | `Bridge.live_quotes` + 游标                          | 每次调用                         | 快照覆盖价格，增量保留五档             |
| 分时           | `Bridge._minute_cache`                               | 10s                              | 推送传 `fresh=true` 绕过               |
| 五日           | `Bridge._five_day_cache`                             | 60s                              | 推送传 `fresh=true` 绕过               |
| K 线           | `Bridge._kline_cache`                                | 60s                              | 首屏 `cacheOnly` 读本地 parquet        |
| 实时 K 线      | `Bridge._kline_live_cache`                           | tail 20 根；60s 补全量           | 断层自动重取全量；tail 不落盘          |
| 涨跌家数       | `Bridge._breadth_cache`                              | 交易 15s / 午休 120s / 收盘 300s | 跨北京时间日期失效                     |
| 行情非交易时段 | `_quote_interval()`（Python）                        | 10 倍、最少 30s                  | 客户端不再各写一套向量                 |
| 交易日历       | `trading_calendar.py`（TDX 官方节假日文件 + 0x120F） | 启动/每 5 分钟 `market_status`   | `holiday` 会话；官方文件覆盖 2025–2026 |

**禁止**在 TS 里再出现用于**业务决策**的行情缓存、TTL、`limitUp` 统计、
全量/断层判断。渲染层唯一允许的“合并”是把 Python 推来的 tail 追加进图表的
只读展示缓冲（否则每秒重传 800 根不可接受）；它必须与 Python `merge_kline_bars`
使用同一组测试向量，且不能用于缓存失效或指标计算。

需要新增缓存时，先加 Python 方法 + 测试，再让统一的 HTTP 适配器转发。

## 六、一致性怎么保证

### 6.1 编译期

- `src/shared/api.ts` 的 `PythonTdxApi` 只有一份实现
  （`src/renderer/src/lib/http-api.ts`）；漏实现方法直接编译失败。
- `src/shared/desktop.ts` 是壳能力契约；preload 与 Web 降级实现都按它实现。
- `src/shared/types.ts` 是字段契约；Python 返回的字段由 Python 测试锁住。

### 6.2 测试期

- Python：`test_tdx.py` 覆盖缓存/TTL/K 线增量/涨跌家数；`test_server.py` 覆盖
  HTTP 路由与 `fresh` 透传；`test_live_quotes.py` 覆盖行情合并顺序。
- TypeScript：`market.test.ts` 覆盖 `pollDelayMs`/时段边界；`workspace.test.ts`
  覆盖标签页打开/关闭；`realtime.test.ts` 覆盖 tail 合并。
- 同一组时段/TTL 向量必须同时出现在 Python 与 TS 测试里（当前：交易/竞价、
  午休、收盘、周末、临近边界不足 500ms）。

### 6.3 发布前人工核对

- [ ] 新增/修改的能力在第四节映射表里能找到 `/api` 入口；
- [ ] 两端参数名/默认值/错误语义一致；
- [ ] 没有新增 TS 行情缓存/合并/统计；
- [ ] `npm run check` 全绿；
- [ ] Web 与 Electron 各截一张关键界面，数字/涨跌色/时间一致；
- [ ] 更新 `CHANGELOG.md` 与 `docs/07` 的验证记录。

## 七、当前边界与刻意取舍（2026-11-14：无未偿还代码债）

| 边界                                   | 影响                                        | 计划                                               |
| -------------------------------------- | ------------------------------------------- | -------------------------------------------------- |
| UI 状态桌面写文件、Web 写 localStorage | 多浏览器/多设备不同步                       | 刻意保留：离线可用、非行情数据；不是通讯协议债务   |
| 面板级推送已下沉到 Python              | 无（`PushManager` + `/api/push` SSE）       | 已完成；3 个 Python 用例覆盖首帧/竞态/隔离         |
| 备份/恢复进度已接 SSE                  | 无（`/api/progress`）                       | 已完成；`DataPanel` 显示真实百分比                 |
| 渲染层保留 K 线只读展示缓冲并合并 tail | 只影响绘制；权威缓存仍在 Python             | 已与 Python `merge_kline_bars` 共用测试向量，禁止扩散 |
| 交易日历内置 2025/2026                 | 2027 年未覆盖时按工作日 + 0x120F            | 每年 12 月更新 TDX 官方快照                        |
| 搜索索引在 TS 本地构建                 | 只影响搜索体验，不影响行情                  | 代码表源头仍是 Python                              |
| 本地 HTTP 服务端口随机                 | 浏览器收藏/多端访问需要固定端口             | 桌面用随机端口；Web 用 8765，可自行反代            |

## 八、反模式清单

| 不要                                         | 应该                                           |
| -------------------------------------------- | ---------------------------------------------- |
| 给 Electron 再加一条 IPC 行情通道            | 统一 `/api` / `/ws`；IPC 只留壳能力            |
| Web 端自己决定 K 线尾部窗口/缓存/TTL/断层    | 调 Python `kline_live`，只把 tail 合进展示缓冲 |
| 桌面主进程缓存分时/K 线并设 TTL              | Python `minute_cached` / `kline_cached`        |
| 两端各写一个涨跌家数扫描/缓存                | Python `breadth_begin/step`                    |
| 在渲染层 `setInterval(fetch)` 组件内自建轮询 | `subscribePush` + 统一适配器调度               |
| 组件直接读 `window.desktop` / `fetch`        | `lib/client.ts` + `stores/**`                  |
| 某端“先补一个兜底”，另一端没补               | 修 Python 或统一适配器，两端同时生效           |
| 只改一端路由/参数                            | 按第四节映射表同时改 `/api` + 测试             |
