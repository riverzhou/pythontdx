# 22 · 前端设计与开发方案

> 基线：pythontdx v1.7.0（2026-11）
>
> 适用：数据密集型、长时间运行、桌面优先的 Electron / Web 双端应用
>
> 目标：让界面在长期迭代中保持可读、可测、可迁移。本文只讨论前端结构、设计系统与工程实践，不依赖具体行情业务。

---

## 1. 目标与边界

行情终端和普通后台不同：用户会长时间盯着同一块屏幕，数字每秒变化，任何布局抖动、错位或误导性颜色都会被放大。方案的第一原则是“让信息稳定地可读”，而不是“把功能堆上去”。

| 目标           | 落地手段                                                                | 可验证结果                                       |
| -------------- | ----------------------------------------------------------------------- | ------------------------------------------------ |
| 一屏完成主任务 | 三栏网格 + 锁死视口高度，只让图表吸收剩余空间                           | 主界面不出现整页滚动条                           |
| 数字可读且不抖 | 等宽数字字体、`tabular-nums`、统一格式化函数                            | 价格跳动时右侧列不左右位移                       |
| 更新快但不闪烁 | 局部信号更新、数值变化高亮、保留上一帧                                  | 1 秒刷新时布局和滚动位置稳定                     |
| 两端同构       | 共享 `renderer` / `shared` / tokens；数据只来自 Python 后端的同一批方法 | 同一组件在 Electron 与浏览器拿到逐字段一致的数据 |

**适用边界**：适合数据密集、长时间运行、桌面优先的应用，例如行情、监控、交易、工业看板。它是工程化方案，不是通用 UI 组件库；视觉部分需要按各自品牌替换令牌，结构部分可以直接复用。

**不建议直接套用**：内容型网站、移动端优先的消费应用、需要复杂路由和 SEO 的多页应用。

## 2. 分层架构

双前端最容易失控的地方，是桌面壳、Web 壳和渲染层互相渗透。解决办法不是“约定”，而是把依赖方向做成硬约束：共享层不碰平台，渲染层不碰传输，壳层不碰业务。

```text
Desktop shell (Electron main / preload)
        │
        ▼
src/renderer (SolidJS components / stores / lib / styles)
        │
        ▼
src/shared (types + pure functions)
        │
        ▼
Python backend (HTTP / WebSocket / protocol / cache)
```

Web 端把最上面一层换成 `src/web`：它用 HTTP / WS 实现同一份 `PythonTdxApi`，下面完全复用。

| 位置           | 可以做什么                                                        | 明确禁止                                                           |
| -------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------ |
| `src/shared`   | 类型、常量、纯展示函数、双端共用的调度策略                        | import `electron`、`node:*`、DOM API；读写全局状态；第二套行情逻辑 |
| `src/renderer` | 组件、响应式状态、视图逻辑                                        | 直接 import `electron`；直接 `fetch`；直接管理行情定时器           |
| `src/preload`  | `contextBridge` 白名单，把壳能力映射成 `window.desktop`           | 暴露 `ipcRenderer` 本身；把 Node 能力整体透传                      |
| `src/main`     | 窗口、托盘、菜单、更新、后端进程守护、传输调度（何时调用 Python） | 写业务 UI；解析/合并/缓存行情；再建第二套数据源                    |
| `src/web`      | 用 HTTP / WS 实现同一份 API 契约                                  | 复制一套组件；让浏览器直接连二进制行情端口                         |

判断标准：如果一个模块同时需要 DOM 和 Node，它大概率放错了层。共享层只允许“输入数据 → 输出数据”的纯逻辑；平台差异必须在壳或适配层收口。

### 目录约定

```text
src/
  main/           Electron 主进程：窗口、托盘、IPC 注册、服务调度
  preload/        contextBridge 白名单桥
  renderer/
    components/   业务组件与基础组件
    stores/       全局状态切片
    lib/          响应式工具、传输封装、图表几何
    styles/       tokens / base / components / app
  shared/         双端共享的类型与纯函数
  web/            Web 外壳与 HTTP API 适配器
python/           协议、行情、缓存、数据湖
```

## 3. 设计令牌

颜色、字号、间距、圆角、阴影、动效时长全部集中在 `styles/tokens.css`。组件只消费语义变量，不写十六进制值；换肤、换品牌、做浅色模式时只改一个文件。

### 3.1 样式层次与导入顺序

```text
tokens.css        变量：颜色、字号、间距、圆角、动效、布局尺寸
base.css          重置、排版、滚动条、通用动画、焦点环
components.css    通用小件：卡片、按钮、标签、分段控件、骨架屏、开关
panels/*.css      业务面板：market / f10 / tools / settings / reports / shell
layout/*.css      应用骨架：shell（标题栏/侧栏）/ workspace（主区/右栏）/ tuning（精修）
```

入口只引入一次，顺序不能颠倒（层叠顺序就是 CSS 的语义）：

```ts
import './styles/tokens.css'
import './styles/base.css'
import './styles/components.css'
import './styles/panels/market.css'
// …其余 5 份 panels，按固定顺序
import './styles/layout/shell.css'
import './styles/layout/workspace.css'
import './styles/layout/tuning.css'
```

新增面板样式放进对应的 `panels/` 文件；只有在写「应用骨架」时才动 `layout/`。

### 3.2 令牌分类

| 类别   | 示例                                                                     | 约束                                               |
| ------ | ------------------------------------------------------------------------ | -------------------------------------------------- |
| 排版   | `--font-ui`、`--font-num`、`--fs-2xs` 至 `--fs-3xl`                      | 正文 13–14px；数字列必须用 `.num` + `tabular-nums` |
| 间距   | `--sp-1` 4px 到 `--sp-8` 32px                                            | 4px 基数；布局间距用 Grid/Flex `gap`               |
| 形状   | `--r-xs` 6px 到 `--r-full` 999px                                         | 同一层级共用同一档圆角                             |
| 动效   | `--dur-1` 120ms、`--dur-2` 200ms、`--dur-3` 320ms                        | 只动 `transform` / `opacity` / 背景色              |
| 布局   | `--titlebar-h` 44、`--statusbar-h` 28、`--sidebar-w` 280、`--rail-w` 330 | 窗口变窄只收侧栏，不压缩主图                       |
| 语义色 | `--up` / `--down` / `--flat`、`--accent`、`--panel`、`--border`          | 涨跌色是业务语义，不能当品牌强调色                 |

### 3.3 主题切换

主题只改根元素属性，组件不做分支：

```css
:root,
:root[data-theme='dark'] {
  color-scheme: dark;
  --bg-base: #07090e;
  --panel: rgba(255, 255, 255, 0.032);
  --text-1: #e9edf7;
  --accent: #5b8cff;
  --up: #ff5470;
  --down: #14c98c;
}

:root[data-theme='light'] {
  color-scheme: light;
  --bg-base: #f2f4f9;
  --panel: rgba(255, 255, 255, 0.72);
  --text-1: #0f1729;
  --accent: #2f6bff;
  --up: #e5384f;
  --down: #0a9e6e;
}
```

```ts
createEffect(() => {
  document.documentElement.dataset.theme = appState.settings.theme
})
```

注意：

- `color-scheme` 必须跟着主题设置，否则滚动条、原生表单控件还是另一套颜色。
- 浅色主题不是把深色值反过来；要单独校准文字对比度、边框透明度和图表网格线。
- 所有颜色先定义在 `:root`，再在 `[data-theme]` 里覆盖。不要在媒体查询里只定义某个颜色，否则未显式选主题时会落到另一套地面色上。

### 3.4 数字排版

价格、涨跌幅、成交量必须使用等宽数字槽位，否则每秒刷新时数字宽度变化会让整列左右抖动。

```css
.num {
  font-family: var(--font-num);
  font-variant-numeric: tabular-nums;
  font-feature-settings: 'tnum' 1;
  letter-spacing: 0.01em;
}

.up {
  color: var(--up);
}
.down {
  color: var(--down);
}
.flat {
  color: var(--flat);
}
```

涨跌方向只由 `toneOf()` 判定，组件不各自写 `value > 0`：

```ts
export type Tone = 'up' | 'down' | 'flat'

export function toneOf(value: number | null | undefined): Tone {
  if (value == null || !Number.isFinite(value) || value === 0) return 'flat'
  return value > 0 ? 'up' : 'down'
}
```

迷你走势图的颜色必须以昨收为基准，而不是“末点减首点”。否则高开回落的股票会出现“线是绿的、旁边涨跌幅是红的”的自相矛盾。这个判断封装在 `sparklineTone(values, baseline)` 里。

## 4. 布局系统

### 4.1 三栏一屏

应用骨架是“三行三列” Grid：

- 行：标题栏 / 内容区 / 状态栏
- 列：侧栏 / 主工作区 / 右栏

```css
.app {
  display: grid;
  grid-template-columns: var(--sidebar-w) minmax(0, 1fr) var(--rail-w);
  grid-template-rows: var(--titlebar-h) minmax(0, 1fr) var(--statusbar-h);
  height: 100%;
  overflow: hidden;
}

.app--empty {
  grid-template-columns: var(--sidebar-w) minmax(0, 1fr) 0;
}
```

核心约束：

1. **只有主图伸缩**：图表卡片用 `1fr` 吸收剩余高度，其余部件是内容高度。避免“列表越高、图表越矮”的连锁反应。
2. **`minmax(0, 1fr)`**：主列必须允许收缩到 0，否则内部长文本或表格会把整个 Grid 撑破。
3. **空状态收起右栏**：没有选中对象时右栏宽度变 0，把空间让给空状态插画。
4. **侧栏可调但不失控**：拖拽手柄用 Pointer Events，宽度夹在合理区间；双击复位；宽度写回设置。
5. **平台差异交给属性**：macOS 红绿灯位置通过 `html[data-platform='darwin']` 留白，不在组件里判断平台。
6. **单一主窗口**：1.7.0 起行情面板全部进主区标签，不再有独立图表/第二主窗口。
7. **分辨率基线**：设计基准 1920×1080，最低支持 1440×900；低于 1440×900 不设适配目标，窗口最小尺寸直接卡死。
8. **1440×900 不出横向滚动条**：列表类窗口优先「收列 / 收留白 / 固定列宽 + 长文本折行」，
   不靠横向滚动解决问题；表宽按 wrap 的**内容宽**（扣掉左右 padding）计算。
9. **默认最大化启动**：首次启动直接最大化；从最大化还原时默认回到 1440×900；之后记住「上次退出时是否最大化」和正常窗口尺寸，用户还原过就按记住的尺寸打开（截图工具按设计跳过最大化）。

### 4.2 主区标签 vs 弹窗

1.7.0 起把二级界面分成两类，不再一律用全屏模态：

**A. 行情显示 → 主区标签**（排行榜、板块/概念、全部 A 股、多股同列、
条件选股、自选行情墙、逐笔明细、复盘、组合分析、预警、龙虎榜、异动、大盘资料）。
它们用 `stores/workspace.ts` 管理标签，面板组件加 `embedded` 后铺满
`.workspace__body`，不写路由：

```tsx
<div class="panel-embed" role="region" aria-label="排行榜">
  <section class="ranking">…</section>
</div>
```

- 标签可关闭；关闭当前标签回到相邻标签，全部关闭回到「行情」；
- 非「行情」标签时右栏整列收起，列表/多股拿到完整宽度；
- 点击列表行 → 写 `activeCode` + 切回「行情」标签，标签本身保留。

**B. 配置/资料 → 弹窗**（设置、数据工具、F10、公告、公式、指标、服务器、
快捷键）。统一结构：

```tsx
<div class="panel-backdrop" onClick={() => props.onClose()}>
  <section class="panel" role="dialog" aria-modal="true" aria-label="面板标题">
    …
  </section>
</div>
```

为什么这些“适合弹出”：

- **设置 / 服务器 / 快捷键**：全局配置或一次性帮助，打开时用户本来就要暂停看行情；
  需要明确的“关闭/应用”边界，弹窗能把注意力锁在配置上。
- **数据工具**：长表格、任务进度、日志，属于“后台任务管理”，不是持续盯盘内容；
  弹窗避免误触同步任务，也不占主图面积。
- **F10 / 公告**：长文本/大表格/外链，是查阅型资料，不是实时报价列表；
  弹一层可以保留下面的图表与选中股票，关闭后回到原上下文（通达信同样用独立资料窗）。
- **公式 / 指标**：编辑器有草稿/取消语义，弹窗天然适合“改完再关”。

共同要求：`Escape` 关闭；backdrop 点击关闭；打开时焦点进入，关闭后回到触发按钮。

**为什么不用路由**：这些界面是“当前主界面的上下文操作”，关闭后必须回到原来的
滚动位置、选中对象和图表状态；用 workspace store 的标签/弹窗状态比路由栈更直接。

### 4.3 导航：三层，一个功能只留一个入口

1.8.0 之前标题栏有「报价 / 分析 / 资讯 / 工具」四个下拉菜单，同一个页面在菜单和
标签栏「+」里各出现一次，进一个页面要点两次。现在按作用域分三层：

| 层           | 位置                  | 放什么                     | 例子                                                     |
| ------------ | --------------------- | -------------------------- | -------------------------------------------------------- |
| 左栏顶部     | `Sidebar`             | 快捷页按钮 + 列表操作      | 排行/全A/板块/多股/选股/行情墙、自选/板块/自定义、新建、收起 |
| 右上角工具区 | `TitleBar`            | 全局工具与配置（弹窗/开关） | 导航栏开关、预警、数据、服务器、快捷键、设置、主题       |
| 主区标签栏   | `WorkspaceTabs` 的「+」 | 所有工作区页面（完整目录） | 排行榜、全部 A 股、板块、多股同列、选股、复盘、龙虎榜… |

规则：

- **「+」是完整目录**：按行情 / 分析 / 资讯分组，带 60 / 63 / F9 / 77 快捷键提示；
- **左栏快捷页栏是快捷方式**：只放最常用的 6 个（排行榜、全部 A 股、板块、多股同列、
  条件选股、自选行情墙），按钮 `flex: 1 1 0` 等分宽度，侧栏拖到最窄 200px 也不溢出；
- **工具只从右上角进**：统一图标风格（同一尺寸/间距/悬停），文字说明放 `title`；
- **导航栏开关**在右上角工具区（面板图标）；左栏面板内的 `«` 保留为就地收起，
  收起后不留任何左侧把手，内容直接铺满；
- 预警的唯一入口是右上角铃铛（带未读数），板块选择的唯一入口是左栏「板块」页签，
  两者都不进「+」，避免重复。

### 4.4 Web / Electron 一致性

两端共用同一套渲染层，差异只能出现在外壳与传输层。2026-11-14 用同一份 DOM 探针
（Electron 当浏览器加载 `out/web`）核对过：

| 检查项 | Electron | Web | 结论 |
| --- | --- | --- | --- |
| 标题栏工具（预警/数据/服务器/快捷键/设置/主题） | 6 | 6 | 一致 |
| 窗口按钮（全屏/最小化/最大化/关闭） | 4 | 0 | 平台差异（Web 无窗口壳） |
| 左栏「导航」+ 6 快捷页 + 3 视图 | ✓ | ✓ | 一致 |
| 「+」菜单项数 / 分组 / 宽度 / 视口内 | 12 / 3 / 150px / ✓ | 同 | 一致 |
| 全部 A 股行数 / 迷你走势 / 表头 sticky / 横向溢出 | 200 / ✓ / sticky / 0 | 同 | 一致 |
| 弹窗（数据/设置/服务器/快捷键/F10/公告） | 6 个均可开关 | 同 | 一致 |
| 深浅主题切换 | ✓ | ✓ | 一致 |
| 控制台错误 | 0 | 0 | 一致 |

**有意保留的差异**：

1. 窗口按钮与拖拽区只存在于 Electron；Web 用浏览器自身窗口。
2. `F11`：桌面切应用全屏，浏览器切 `document.fullscreenElement`（同一按键、同一语义）。
3. 设置里的「浏览器通知」只在 Web 出现；桌面走系统通知，无需授权 UI。
4. 备份/恢复要读写本机文件：浏览器版按钮置灰并提示「请在桌面端操作」，桌面走原生
   文件对话框；数据湖/导出在两端都可用（Web 走下载）。

## 5. 组件设计

### 5.1 五类组件

| 类型     | 代表                                                  | 职责边界                                     |
| -------- | ----------------------------------------------------- | -------------------------------------------- |
| 基础控件 | Card、Button、Tag、Segmented、Skeleton、Switch、Icons | 只负责外观与状态；不读业务 store             |
| 数据行   | WatchRow、SectorRow、TradeTape 行                     | 订阅自身需要的快照；拖拽/右键/闪烁在行内闭环 |
| 业务面板 | QuoteHeader、ChartPanel、F10Panel、RankingPanel       | 通过 props 拿上下文；数据加载走 stores/lib   |
| 图表     | TrendChart、KLineChart、IndicatorSubchart、Sparkline  | 只画传入的数据；坐标计算全部是纯函数         |
| 覆盖层   | SettingsPanel、ShortcutsPanel、AlertToast、StockMenu  | 统一 dialog / backdrop / Escape 行为         |

### 5.2 组件契约

- 数据从 props 进，事件从回调出。
- 展示组件不直接请求数据；容器组件负责取数，再把纯数据传下去。
- 业务面板由根组件注入 `code` / `name` / `onClose` / `onSelect`，不自己去全局路由里找。
- 不把 Solid store 的 Proxy 直接跨进程传输；传之前用 `plainXxx()` 拍平。

```ts
export interface WatchRowProps {
  item: WatchItem
  index: number
  groupId: string
}

export function WatchRow(props: WatchRowProps): JSX.Element {
  const quote = () => quoteOf(props.item.code)
  const active = () => appState.activeCode === props.item.code
  // 拖拽、删除、右键菜单都在行内完成；
  // 父级只负责提供 item / index / groupId。
}
```

### 5.3 交互清单

每个可点击对象都要过一遍：

| 状态     | 必须存在的行为                                 |
| -------- | ---------------------------------------------- |
| hover    | 背景/边框变化，且不改变尺寸                    |
| active   | 独立背景 + 左侧高亮条，不能只靠文字变色        |
| focus    | 全局 `:focus-visible` 焦点环，键盘可达         |
| disabled | 降低透明度 + `cursor: not-allowed`，不响应点击 |
| drag     | 拖拽源淡出，落点画线；拖到自己身上不显示落点   |
| context  | 右键菜单可关闭，点击外部或 Escape 退出         |
| empty    | 空列表给引导文案，不留纯空白                   |

### 5.4 搜索框：完整的输入模式

搜索是高频入口，把“防抖、竞态、键盘、最近记录、纯代码兜底”一次性做全：

- 输入防抖 240ms。
- 每次请求带递增序号，只接受最后一次响应。
- 上下键循环选择，Enter 提交。
- 输入框失焦后延迟 140ms 关闭弹层。
- 无匹配时允许直接输入 6 位代码加入。
- 空输入时显示最近搜索。
- 拼音索引按需加载，避免拖慢首屏。

```ts
let sequence = 0

createEffect(
  on(keyword, (value) => {
    const token = ++sequence
    const timer = setTimeout(() => {
      api.search.hint(value).then((result) => {
        if (token !== sequence) return
        setItems(result)
        setOpen(true)
      })
    }, 240)
    onCleanup(() => clearTimeout(timer))
  })
)
```

**踩坑提醒**：弹层项的 `mousedown` 必须 `preventDefault()`。否则输入框先失焦、140ms 后弹层被移除，用户点得稍慢时 `click` 落在已移除的节点上，表现为“点了没反应、偶尔成功”。

## 6. 状态管理

### 6.1 渲染层是唯一数据源

用户的每一次操作先改本地 store，界面立即响应；持久化异步进行，失败只记日志，不回滚已经发生的交互。主进程只负责保存，不参与界面状态判断。

| Store               | 内容                                       | 生命周期               |
| ------------------- | ------------------------------------------ | ---------------------- |
| `stores/app`        | 自选分组、设置、选中代码、预警、公式、持仓 | 应用级，启动时恢复     |
| `stores/quotes`     | `quoteMap`、连接状态、最后更新时间、错误   | 应用级，Python 订阅推送驱动 |
| `stores/clock`      | 全局 1 秒时钟                              | 根组件启动一次         |
| `stores/sparklines` | 迷你走势缓存与并发加载                     | 按可见列表懒加载       |
| `stores/alerts`     | 预警规则与最近事件                         | 应用级                 |
| `stores/stockMenu`  | 右键菜单坐标与目标                         | 一次交互               |

### 6.2 写状态的固定顺序

```ts
export function updateSettings(patch: Partial<AppSettings>): void {
  // 1. 先改本地状态：界面立即响应
  setState('settings', patch)

  // 2. 再异步落盘：不阻塞交互
  const settings = plainSettings()
  persist({ settings })

  // 3. 需要跨窗口同步时广播
  postWindow({ type: 'settings', settings })
}
```

Solid store 是 Proxy，跨 IPC / localStorage 传输前必须转成纯对象，否则 Electron 的结构化克隆会报 “could not be cloned”。统一用 `plainGroups()`、`plainSettings()` 这类函数拍平，不在调用点临时展开。

### 6.3 派生状态，不复制状态

能从现有状态算出来的，不再存一份：

- “当前分组的股票”由 `activeGroup()` 派生。
- “全部订阅代码”由 `watchCodes()` 从 groups 去重计算。
- “能否涨停”由价格和涨跌停价实时计算。

复制状态会带来同步 bug，而派生函数的成本可以忽略。

### 6.4 生命周期与竞态

- **全局时钟只启动一次**：`startClock()` 幂等；所有“现在几点”的 UI 共享同一个信号，避免多个定时器差一秒。
- **订阅必须可清理**：组件在 `createEffect` 里订阅，在 `onCleanup` 里取消；切 tab、关面板不留下孤儿定时器。
- **旧响应不能覆盖新响应**：搜索用递增 token，F10 用 `requestId`，图表切换用 `cancelled` 标志。
- **首屏先用缓存**：Python 侧 `kline_cached(cacheOnly)` 先读本地 parquet，网络回来后再覆盖；行情推送晚 250ms 启动，把队列先让给图表缓存与首屏数据。
- **多窗口同步**：用 `BroadcastChannel` 广播选中代码和设置，避免每个窗口各存一份互相漂移。

## 7. 数据与传输

### 7.1 一份契约，一份实现

桌面与浏览器都走本地 HTTP / WebSocket，组件看到的永远是同一份 `api`。契约集中在 `shared/api.ts`，类型集中在 `shared/types.ts`；壳能力在 `shared/desktop.ts`，由 `window.desktop` 或 Web 降级实现提供。

```ts
export interface PythonTdxApi {
  quote: {
    snapshot(codes: string[]): Promise<Quote[]>
    subscribe(codes: string[], intervalMs: number): Promise<void>
    unsubscribe(): Promise<void>
    onUpdate(listener: (update: QuoteUpdate) => void): () => void
  }
  trend: {
    minute(code: string): Promise<MinuteTrend>
    kline(request: KLineRequest): Promise<KLineSeries>
  }
}
```

| 能力        | 桌面                                       | Web                            |
| ----------- | ------------------------------------------ | ------------------------------ |
| 请求 / 响应 | `fetch` JSON → 本地 Python                 | `fetch` JSON → 本地 Python     |
| 实时行情    | WebSocket → SSE → 轮询三级降级             | 同一份实现                     |
| 面板推送    | `/api/push` SSE；服务端 `PushManager` 调度  | 同一份实现                     |
| 本地状态    | `window.desktop.state`（文件）             | `localStorage`                 |
| 窗口能力    | 真实窗口 / 托盘 / 多屏                     | 返回虚拟信息，不支持的明确报错 |

### 7.2 安全模型

Electron 窗口固定 `contextIsolation: true`、`nodeIntegration: false`；渲染层拿不到 `require` / `process`。preload 只暴露壳能力：

```ts
contextBridge.exposeInMainWorld('desktop', {
  window: { control: (action) => ipcRenderer.invoke(NATIVE_IPC.windowControl, action) },
  dialogs: { save: (options) => ipcRenderer.invoke(NATIVE_IPC.dialogSave, options) }

// 严禁：等于关掉整个隔离层
contextBridge.exposeInMainWorld('ipcRenderer', ipcRenderer)
```

所有异常在适配器里洗成可展示的中文（`errorMessage()`）。

**组件侧铁律**：组件不直接 `fetch`，也不直接读 `window.desktop`。调用点收敛在 `lib/client.ts` 和 `stores/**`。

## 8. 实时调度

### 8.1 行情调度在 Python，展示定时器在适配器

行情订阅由 Python `SubscriptionHub` 统一调度（SSE/WS），同一组代码只轮询一次，收盘/午休由 `_quote_interval()` 降频。渲染层只声明代码集合与间隔，不再有桌面 Poller 与 Web 适配器两套调度。

面板级推送（分时/逐笔/竞价/K线）也由 Python `PushManager` 统一调度：客户端只打开一条 `/api/push` SSE 并登记任务 id，断线重连用稳定 id 恢复；渲染层不再持有面板 Timer。

| 场景        | 策略                         | 原因                             |
| ----------- | ---------------------------- | -------------------------------- |
| 交易时段    | 用户设置间隔，默认 1000ms    | 分时 / K 线要求 1 秒可见         |
| 午休 / 收盘 | 自动降到 30s 以上            | 没有新成交，快轮询只会被上游限流 |
| 时段边界    | 下一次唤醒压在边界 +250ms    | 避免低频定时器把开盘拖后 30 秒   |
| 窗口不可见  | 页面 `hidden` 时暂停面板拉取 | 切到别的应用时省上游压力         |
| 请求进行中  | `inFlight` 防重入            | 慢请求不会叠成一串               |
| 连续失败    | 1s / 2s / 4s / 8s / 10s 退避 | 断线快速重连，又不制造重试风暴   |

```ts
private schedule(delay?: number): void {
  const wait = delay ?? Math.min(
    this.effectiveInterval(),
    msUntilSessionChange() + 250
  )
  this.timer = setTimeout(() => void this.tick(false), wait)
}

private async tick(force: boolean): Promise<void> {
  if (this.inFlight) return
  if (!force && this.options.canFetch && !this.options.canFetch()) {
    this.schedule()
    return
  }
  // ... fetchQuotes；失败时 failures += 1
  const retryDelay = this.failures > 0
    ? Math.min(1000 * 2 ** (this.failures - 1), 10_000)
    : undefined
  this.schedule(retryDelay)
}
```

### 8.2 面板级推送

分时、逐笔、竞价、资金流等面板不各自 `setInterval`。它们调用 `subscribePush(task, intervalMs, onData)`；服务端 `PushManager` 按 task 建订阅、线程内串行拉取并立即推首帧，之后按链式间隔推送。客户端卸载时只注销订阅 id，服务端线程随之收敛。

```ts
createEffect(() => {
  const dispose = subscribePush<AuctionPoint[]>(
    { kind: 'auction', code: props.quote.code },
    1000,
    (points) => setAuction(points.at(-1) ?? null)
  )
  onCleanup(dispose)
})
```

首帧优先：服务端订阅线程启动即拉一次，面板不用再单独 load；同一客户端断线重连时按稳定 id 重新登记，组件不需要重建图表。

## 9. 图表与性能

### 9.1 手写 SVG + 纯函数几何

分时、K 线、副图全部手写 SVG，不引入图表库。坐标换算、窗口缩放、刻度、均线、区间统计都抽到 `lib/chart-geometry.ts`：输入数据与画布尺寸，输出数字，不碰 DOM，也不依赖 SolidJS。

原因：

- **可控**：十字光标联动、区间统计、画线、除权标记这些交互，图表库的扩展成本往往高于自己画。
- **可测**：“第 137 个点的 y 坐标”可以用单元测试锁住，不必靠截图肉眼判断。
- **可读**：组件只负责把返回的数字塞进 SVG，读代码时不会被坐标运算淹没。

```ts
export interface TrendGeometry {
  width: number
  height: number
  x(slot: number): number
  yPrice(value: number): number
  yVolume(value: number): number
  totalSlots: number
  slotStart: number
  slotEnd: number
}

export function buildTrendGeometry(
  days: MinuteTrend[],
  width: number,
  height: number,
  padding: Padding = TREND_PADDING
): TrendGeometry | null
```

### 9.2 尺寸：按真实像素绘制

图表容器用 `ResizeObserver` 量出真实宽高，再按像素绘制。不要用 `viewBox` 缩放：它会把线宽、文字、间距一起拉伸，1px 网格线会变成 1.3px 的模糊线。尺寸没变时不写信号，既省重绘，也避免 `ResizeObserver` 循环告警。

### 9.3 数据量策略

| 环节      | 策略                                                                                          |
| --------- | --------------------------------------------------------------------------------------------- |
| 首屏 K 线 | 一次取 800 根历史；可见窗口最多 500 根，均线用完整 800 根计算                                 |
| 每秒推送  | 只推最近 20 根 tail；Python 合并进 800 根基线，渲染层把 tail append-only 合进展示缓冲         |
| 最新价    | 用 1 秒报价修补最后一根 K 线的 close / high / low；日线补累计成交量，分钟线不把累计量当单根量 |
| 历史数据  | 官方没给的点不伪造；开盘第一秒用昨收造基准点，让坐标系先出现                                  |
| 切换股票  | `createMemo(() => props.code)` 稳定字符串，避免父组件每次推新对象都触发重新拉取               |

**性能红线**：

- 不要每秒把 800 根 K 线全量传一遍。
- 不要为每个面板各起一个 1 秒定时器。
- 不要在切 tab 后留下孤儿请求。
- 正确做法是“首帧全量 + 后续 tail + 统一调度 + 卸载清理”。

## 10. 可访问性与细节

桌面端的质感来自大量小决定：默认不可选中、焦点环清晰、数字不抖、弹层可 Escape、动画尊重系统设置、错误永远不显示 NaN。

| 细节 | 做法                                                                                       |
| ---- | ------------------------------------------------------------------------------------------ |
| 键盘 | `/` 聚焦搜索、`r` 刷新、`t` 切主题、`?` 快捷键、`F10` 公司资料、`F11` 全屏；输入框内不拦截 |
| 焦点 | 全局 `:focus-visible` 焦点环；弹层打开时焦点落在可操作元素                                 |
| 语义 | dialog 用 `role="dialog"` + `aria-modal`；tabs 用 `role="tablist"` + `aria-selected`       |
| 动效 | 120 / 200 / 320ms；`prefers-reduced-motion` 下降到 0.01ms                                  |
| 选择 | body 默认 `user-select: none`；需要复制的文本加 `.selectable`                              |
| 空值 | 所有数字格式化函数对 NaN / Infinity / undefined 返回 `—`                                   |
| 颜色 | 涨跌同时有符号和文字标签，不单靠颜色传达状态                                               |
| 滚动 | 只有列表和代码块内部滚动；页面主体不横向滚动                                               |

```ts
export function fixed(v: number | null | undefined, digits = 2): string {
  return Number.isFinite(v) ? v.toFixed(digits) : '—'
}

export function signedPct(v: number | null | undefined, digits = 2): string {
  return `${signed(v, digits)}%`
}
```

**桌面优先的响应式**：设计基准 1920×1080，最低 1440×900；1440 宽自动收窄侧栏/盘口、指标换两行。低于 1440×900 不做适配（窗口最小尺寸已经卡死）。若要把同一套界面搬到移动端，应先重做布局断点（例如侧栏变抽屉、右栏变底部 sheet），不要只缩小字号。

## 11. 工程质量

方案里的“必须”不能只写在文档里。类型检查、ESLint、测试、构建脚本和视觉验收各管一段，最后用一个 `check` 命令串起来。

| 关卡 | 工具 / 命令                                      | 守住什么                              |
| ---- | ------------------------------------------------ | ------------------------------------- |
| 类型 | `npm run typecheck`（node + web 两套 tsconfig）  | strict、`noUnusedLocals`、跨层契约    |
| 规范 | `npm run lint`（ESLint + `eslint-plugin-solid`） | 响应式陷阱、未使用变量、危险写法      |
| 格式 | `prettier --check`                               | 缩进、引号、换行；不参与 ESLint       |
| 单测 | `npm run test`（Vitest，node 环境）              | 纯函数、store、图表几何、格式化       |
| 后端 | `npm run test:python`                            | 协议解析、缓存、数据任务              |
| 视觉 | `npm run shot`                                   | 构建后截图，肉眼验收主界面            |
| 总闸 | `npm run check`                                  | typecheck + lint + test + python test |

### 可测试性来自拆分，不来自 mock

- **纯函数优先**：格式化、交易时段、代码归一化、搜索排序、图表几何都不碰 DOM，测试直接给输入断言输出。
- **真实报文当 fixture**：协议解析用抓包数据，不用手写“理想 JSON”；容错分支才有意义。
- **关键路径加 `data-testid`**：只给稳定的交互锚点，不把整棵树都打上标记。
- **测试环境保持极简**：Vitest 默认 node，不引入 jsdom；需要 DOM 的组件测试再单独配置。

### 依赖策略

运行时依赖保持最少：SolidJS、Vite 插件、拼音库等；图表、图标、弹层、拖拽、格式化全部自写。依赖越少，升级和排查成本越低。

### 注释原则

注释解释“为什么”，不解释“是什么”。踩过的坑必须留痕：

```ts
// 成交量是累计值，图表里需要的是“每分钟增量”
const volume = Math.max(0, cumulativeVolume - lastCumulativeVolume)
```

## 12. 复用与迁移

其他项目不需要照搬业务。可以复用的是“结构”，需要替换的是业务类型、色板、交易时段和具体数据接口。

### 12.1 直接复制

| 资产            | 路径                                                                        | 迁移时改什么                                             |
| --------------- | --------------------------------------------------------------------------- | -------------------------------------------------------- |
| 令牌 + 基础样式 | `styles/tokens.css`、`base.css`                                             | 替换品牌色、字体；保留字号 / 间距 / 动效层级             |
| 三栏骨架        | `styles/layout/shell.css` 与 `workspace.css` 的 `.app` / `.workspace` / `.rail` | 按业务调整列宽与是否可收起                              |
| 基础控件        | Card、Button、Tag、Segmented、Skeleton、Switch                              | 只改视觉，不改交互契约                                   |
| API 契约模式    | `shared/api.ts`、`shared/desktop.ts`、`lib/http-api.ts`、`preload/index.ts` | 替换方法名与数据结构；保留“一份数据契约、一层壳能力”     |
| 实时调度        | `python/subscription_hub.py`、`python/push_manager.py`                       | 替换“调用哪个 Python 方法”；保留退避 / 时段策略           |
| 图表几何        | `lib/chart-geometry.ts`                                                     | 替换坐标域；保留“纯函数 + 单测”                          |
| 状态模式        | `stores/app.ts` 的写状态顺序                                                | 替换领域字段；保留“先响应、后落盘、纯对象传输”           |

### 12.2 六步接入

1. **先落令牌**：把颜色、字号、间距、圆角、动效集中到一个文件；组件里禁止散落色值。
2. **再搭骨架**：用 Grid 做“工具栏 / 侧栏 / 主区 / 右栏 / 状态栏”，先保证一屏不滚动。
3. **定契约**：先写 shared 类型与 API 接口，再写桌面 / Web 两个实现；不要先写页面再倒推。
4. **收状态**：每个领域一个 store；更新顺序固定为“本地 → 异步落盘 → 跨窗口广播”。
5. **接实时**：壳只做传输调度；数据缓存/合并/增量全部在 Python。组件只声明订阅与清理，不自己拉。
6. **补测试**：先把纯函数和几何算出来测，再给关键交互加组件测试；最后用截图做视觉验收。

### 12.3 反模式

| 不要                                   | 应该                                          |
| -------------------------------------- | --------------------------------------------- |
| 组件里 `setInterval(fetch)`            | Python `/ws` Hub + `subscribePush` 声明式订阅 |
| 每个面板各存一份行情                   | 一个 `quoteMap`，所有组件按 code 取           |
| 组件直接 `fetch` 或读 `window.desktop` | 收敛到 `lib/client.ts` 与 stores               |
| shared 里 import electron / node / DOM | 只放类型、常量、纯函数                        |
| 把 NaN / undefined 直接渲染            | 统一格式化函数返回 `—`                        |
| 每秒推全量 K 线                        | 首帧全量，后续 tail                           |
| 用 viewBox 缩放图表                    | ResizeObserver 量真实像素                     |
| 颜色写死在组件里                       | 只消费 `tokens.css` 变量                      |
| 多个组件各起一个时钟                   | 根组件启动一个共享 clock store                |
| 订阅后忘记清理                         | `onCleanup` / 返回 dispose                    |

## 13. 信息密度基线（1.8.0）

行情终端的第一目标是同屏信息量。布局允许“好看”，但不允许为了装饰性留白牺牲
图表高度或表格行数。1440×900 下的实测预算：

| 区域            | 1.7.0 | 1.8.0 | 说明                                         |
| --------------- | ----: | ----: | -------------------------------------------- |
| 标题栏          |  44px |  38px | 搜索/时钟/工具按钮/窗口控制保持可点          |
| 工作区标签栏    |  30px |  26px | 关闭按钮仍保留 26×26 热区                    |
| 行情头          | 148px | 104px | 12 项指标一排；PE/PB/市值作为第二行可选      |
| 图表头          |  84px |  67px | 二级工具默认收起；读数/指标/公式仍在同一行  |
| 主图区          | 525px | 610px | 主要收益来自前四项                           |
| 排行榜同屏行数  |  16 行 |  18 行 | 行高 9px→5px padding                         |

实现原则：

1. 优先压缩容器 padding / gap，不缩小字号层级；最小可点击高度 22px。
2. 表格行高用 `padding-top/bottom` 调，不用固定 `height`，避免高 DPI 截断。
3. 侧栏/右栏宽度默认 264/300；用户拖拽后的值优先，旧默认值自动迁移。
4. 任何新增面板先问：能否作为主区标签页？是否必须弹窗？
5. 1440×900（最低支持分辨率）下允许隐藏辅助提示，但不能隐藏价格/时间/盘口数据。
