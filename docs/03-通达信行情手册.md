> 协议来源：社区逆向实现 [pytdx](https://github.com/rainx/pytdx)、[eltdx](https://github.com/electkismet/eltdx)，
> 以及本项目 2026-10-29 收盘后的实盘抓包。**不是通达信官方 API。**

## 本地文件
写回 .day/.lc1/.lc5/.5 采用原子替换；跨库查询时 stats.db 以 `stats.*` 只读附加；导入数据湖时原始文件按 sha256 放 `local/raw/local/<sha16>/`，规范化写入 `local/normalized/local/`。
`.day` 每条 32 字节：date/open/high/low/close/amount/volume/reserved；价格单位分，成交量股。
GBBQ（`T0002/hq_cache/gbbq`）：`u32 count` + count × 29B；前 24B 为三组 8B
XOR/查表加密（pytdx MIT 密钥），后 5B 明文；解析出市场/代码/日期/类别 + 4 个 float
（category=1 时为分红/配股价/送股/配股，其余类别为股本字段；字段统一输出
`c1..c4` + `categoryName`，避免误读）。`python/gbbq.py` 已用本机 202,313 条实文件验证。
`.lc1/.lc5` 每条 32 字节：压缩日期/分钟数/float32 OHLC/额/量；`.5` 的 OHLC 是整数分。

## 一、为什么是 Python sidecar

行情层是一个独立进程 `python/tdx_bridge.py`：

```
渲染层 ── IPC ──▶ 主进程 services/tdx/index.ts
                          │  JSON Lines（stdin/stdout）
                          ▼
                 Python 子进程 tdx_bridge.py
                          │  TCP 7709
                          ▼
                    通达信行情主站
```

分工：

| 层 | 负责 |
| --- | --- |
| Python | TCP、握手、帧、zlib、变长整数、压缩浮点、字段解析、财务合并 |
| 主进程 TS | 拉起/重启子进程、请求排队、超时、TTL 缓存、代码表 + 拼音搜索 |
| 渲染层 | 只跟 `window.api` 打交道，不知道数据来自 socket 还是 HTTP |

打包时 Nuitka 把脚本编译成单文件，放在 `resources/tdx-bridge/`，不携带 Python 源码；
用户机器不需要安装 Python。开发模式则直接 `python3 python/tdx_bridge.py`。

> **v0.7 目标**：sidecar 升级为 Python 后端服务（HTTP/WS），
> 桌面与 Web 共用；协议层、帧格式、解析函数不变，只是把「stdin/stdout」换成
> 「HTTP 请求 + WebSocket 推送」。迁移细节见 `PLAN.md` P0。

## 二、连接与帧

### 2.1 主站

TCP **7709**，多个主站按顺序 failover。当前 `python/tdx_bridge.py` 的
`ENDPOINTS` 里有 5 个**临时种子**（124.71.187.122 / 180.153.18.170 /
116.205.183.150 / 111.230.186.52 / 119.97.185.59），2026-10-30 实盘请求成功，
但**没有逐台测速，也不是「最新列表」**。

目标策略（`docs/08` 第三节、`PLAN.md` TD21）：

1. 优先读本机通达信客户端 `connect.cfg` 的官方主机表；
2. 其次用带日期的种子列表，启动时用**真实业务命令**并发探活；
3. 用户配置可覆盖；写坏要报错，不静默回退；
4. 不自动拉取远端主机表，避免供应链风险。

主站会变，连不上时先看探活记录，不要再往代码里加一个「看起来能 ping 通」的 IP。

### 2.2 握手

**只发一条 `0x000d`，data = `[0x01]`。**

这是本项目踩到的最大的坑：pytdx 的 `setup1 / setup2 / setup3` 三连包会让服务端
进入旧版会话，之后 `0x053e` 只回 4 字节空包（`01 05 00 00`），看起来像「没有行情」。
改成只发一条握手后，五档、K 线、分时全部正常。

### 2.3 请求帧

12 字节头 + data：

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 1 | 固定 `0x0c` |
| 1 | 4 | msgId，u32 LE；服务端原样回显，任意非零值即可 |
| 5 | 1 | control，固定 `0x01` |
| 6 | 2 | `data.length + 2`，u16 LE |
| 8 | 2 | 同上（协议要求写两遍） |
| 10 | 2 | 命令号，u16 LE |
| 12 | n | data |

### 2.4 响应帧

16 字节头 + body：

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 4 | 固定 `b1 cb 74 00` |
| 4 | 1 | control |
| 5 | 4 | msgId（服务端回显，可能和请求不同） |
| 9 | 1 | 保留 |
| 10 | 2 | 命令号 |
| 12 | 2 | `zipLength` |
| 14 | 2 | `length` |

- 先读 16 字节，再读 `zipLength` 字节；
- `zipLength == length` → 不压缩；否则对 body 做 `zlib.decompress`；
- 每次请求都有 8 秒超时；超时直接销毁连接，下一次请求重连，避免报文错位。

## 三、命令与字段

### 3.1 批量五档 `0x053e`

请求 data：

```
8 字节前缀 [5,0,0,0,0,0,0,0]
u16 数量
每条 7 字节：u8 市场（0 深 / 1 沪 / 2 京）+ 6 字节 ASCII 代码
```

**单次最多 80 只**。实测 81 只和 100 只都只返回 80 条，是静默截断，不会报错。

响应：

```
2 字节头
u16 数量
记录 × N
```

每条记录（变长）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| market | u8 | 0/1/2 |
| code | 6s | ASCII |
| active1 | u16 | 状态原始值 |
| price | varint | 现价，单位 0.01 |
| lastCloseDiff | varint | 现价 + 它 = 昨收 |
| openDiff / highDiff / lowDiff | varint | 相对现价的差分 |
| serverTimeRaw | varint | 时间原始值；**语义未确认**，本项目暂用接收时间 |
| unknown | varint | 时间后的保留字段 |
| totalHand | varint | 总成交量，单位「手」 |
| currentHand | varint | 现手 |
| amount | u32 | 压缩浮点，单位「元」 |
| inside / outer | varint | 内盘 / 外盘 |
| unknown ×2 | varint | 保留 |
| 5 × (bidDelta, askDelta, bidVol, askVol) | varint | 五档，价格 = 现价 + delta |
| tradingStatus | u16 | 交易状态 |
| 4 × tailMetric | varint | 尾部指标 |
| riseSpeed / active2 | i16 + u16 | **可选 4 字节**，部分响应没有 |

**指数成交量单位**：`0x053e/0x054c/0x054b` 的 `totalHand` 对个股是「手」，
对指数是「股」；pythontdx 在 `_build_quote` 统一除以 100 成「手」，与 K 线
`volume` 同单位。MAC `0x122B` 的指数量同样归一。否则实时合并会把历史量柱压成 1%。

价格缩放：`price = raw / (100 × divisor)`，`divisor` 来自代码表的 `decimal`：
`decimal ≤ 2 → 1`，`decimal = 3 → 10`。

**指数的坑**：`sh000001` 的价格字段有效，但五档字段是垃圾值（实测买一价能到 41 万）。
解析时按代码规则识别指数，直接把 `bids` / `asks` 置空。

> **实现边界**：`tradingStatus/4×tailMetric/riseSpeed/active2` 的文档布局与真实
> fixture 对不上（0x054c 可能只有 1 档，0x0547 尾部未确认），pythontdx 暂不输出
> 这些字段，只保留 `timeRaw/currentHand/openAmount/recordHex`。

### 3.2 K 线 `0x052d`

请求 data（42 字节）：

```
u16 市场 + 6 字节代码
u16 周期（4 日 / 5 周 / 6 月）
u16 1
u16 start（0 = 最新）
u16 count（1..800）
u16 adjust（0 不复权 / 1 前复权 / 2 后复权）
u32 锚点（0）
20 字节 0
```

响应：

```
u16 数量
每条：
  u32 日期 YYYYMMDD
  varint openDiff / closeDiff / highDiff / lowDiff
  u32 volume（压缩浮点，股）
  u32 amount（压缩浮点，元）
  指数额外 4 字节：上涨家数 u16 + 下跌家数 u16
```

价格是**差分编码**：`open = base + openDiff`，`close = openRaw + closeDiff`，
`base` 从 0 开始，下一根的 base = 本根 close。价格单位 0.001 元。

- `0x052d` 周期：1m=7、5m=0、15m=1、30m=2、60m=3、日=4、周=5、月=6、季=10、年=11；
  5s/15s 用 period=13 + period_param=5/15，日期是 2003-12-31 起的秒数；
  多分钟（2/3/4/6/8/10/12/18/20/24/36/48）用 period=8 + N；多日线（2/3/4/6/9/12/18/24/45）用 period=9 + N；
分钟 K 日期是 packed date + minute-of-day，不能按 yyyymmdd 解析。
- `adjust=0` 不复权 / `1` 前复权 / `2` 后复权（UI 三态可切）；
  实测 600519 旧价 1713.80 / 1560.28 / 10579.06。
- 成交量 `wire / 100` 得「手」；可转债不再除。
- **指数每条记录多 4 字节**，不跳过会把下一根的日期读歪。

### 3.3 当日分时 `0x0537`

请求 data：`u16 市场 + 6 字节代码 + 00 00 00 93`。

响应：`u16 数量 + u16 保留 + 每条 (priceField, avgField, volume)`，全部 varint。

- 第 0 条是绝对值，之后是相对第 0 条的增量；
- 价格 `/ (100 × divisor)`，均价 `/ (10000 × divisor)`；
- 240 个点，时间不是字段，按序号推：0=09:31，119=11:30，120=13:01，239=15:00；
- **没有日期、没有昨收**，由调用方用不复权日 K 的最后两根补。

### 3.4 历史分时 `0x0fb4`

请求 data：`u32 日期 YYYYMMDD + u8 市场 + 6 字节代码`。

响应：`u16 数量 + f32 昨收 + 每条 (priceDelta, auxDelta, volume)`。

- 价格从 0 开始累加；
- 昨收直接来自响应头，适合五日分时；
- 没有均价字段，本项目用「分钟价 × 量的 VWAP」近似。

### 3.5 代码表 `0x044d` / 数量 `0x044e`

数量请求：`u16 市场 + u32 客户端日期` → `u16 数量`。

代码表请求：`u16 市场 + u32 start + u32 limit + 4 字节 0`，单页最多 1600。

代码表记录定长 37 字节：

| 偏移 | 字段 |
| --- | --- |
| 0 | 代码 6s |
| 6 | multiple u16 |
| 8 | 名称 GBK 16s |
| 24 | 未知 f32 |
| 28 | decimal u8 |
| 29 | 昨收 f32 |
| 33 | 未知 4s |

全量 3 个市场约 5.2 万条，实测 0.75~0.86 秒。名称会用空格做视觉对齐
（`五 粮 液`），必须去掉；英文名只把连续空格压成一个。

### 3.6 财务 `0x0010`

请求 data：`u16 数量 + 每条 (u8 市场 + 6 字节代码)`，单次最多 80。

响应：`u16 数量 + 每条 143 字节`，其中代码 7 字节后是 136 字节财务结构：

| 结构偏移 | 字段 | 单位 |
| --- | --- | --- |
| 0 | 流通股本 f32 | 万股 |
| 16 | 总股本 f32 | 万股 |
| 40 | EPS f32 | 元/股（报告期口径，不是 TTM） |
| 128 | 每股净资产 f32 | 元/股 |

用途：流通市值、总市值、换手率、市净率。
**PE TTM / 量比 / 涨跌停价暂不提供**——EPS 是报告期口径，直接算 PE 会和行情软件的
TTM 差很多；界面这几项显示「—」。

### 3.7 批量快照 `0x054c`

请求 data 与 `0x053e` 相同：`8 字节前缀 05 00... + u16 数量 + 每条 (u8 市场 + 6 字节代码)`，
单次最多 80 只。

响应：`u16 头 + u16 数量`（数量在 `[2:4]`），记录从偏移 4 开始，**长度可变**，
按「市场 + 6 位代码」标记切分。单条记录：

| 偏移 | 字段 |
| --- | --- |
| 0 | 市场 u8 |
| 1 | 代码 6s |
| 7 | active u16 |
| 9 | 五个差分 varint：current / last_close / open / high / low |
| — | 时间 varint、时间后未知 varint |
| — | 总手 varint、现手 varint |
| — | 成交额 u32（压缩浮点） |
| — | 内盘 / 外盘 / 外盘后未知 / 开盘金额（各 varint） |
| — | 买一价差 / 卖一价差 / 买一量 / 卖一量（各 varint） |
| — | 56 字节尾部保留区 |

价格：`current_milli = current_delta * 10`，实际价 = `milli / 1000 / divisor`
（A 股 divisor=1，即 `current_delta / 100`）；买一/卖一价 = `(current_milli + delta*10)` 再除。
盘口**只稳定返回买一/卖一**，不要把它当五档用。

fixture：`python/fixtures/snapshot2.hex`（2026-10-30 实盘，600519 + 000858）。

### 3.8 增量刷新 `0x0547`

请求 data：`u16 数量 + 每条 (u8 市场 + 6 字节代码 + u32 游标)`，单次最多 **100** 只；
首次游标传 0。响应不是明文：**每个字节 XOR 0x93**，解码后 `u16 数量` 在偏移 0，
记录从偏移 2 开始，按「市场 + 代码」标记切分。

**盘中探针**：交易时段运行
`python3 scripts/probe_0547.py --code sh600519 --seconds 120`；
脚本会把 cursor=0/1/0xFFFFFFFF/毫秒时间戳以及连续 loop-zero 请求写到
`lake/probes/0x0547-*.jsonl`，每行含 count/hash/sample，供事后对照。
它只记录响应差异，不直接断言“服务端推送”。

**游标语义：2026-11-02 盘中已确认增量刷新**。2026-10-31 休市时同一连接分别传
`cursor=0`、`1`、`0xFFFFFFFF`，三次均返回 **129 字节 / 1 条记录 / 价格 1392.05 /
记录内 update=153001**，当时只能说明休市无新数据时游标没有差异。

2026-11-02 10:33 用修正后的 `scripts/probe_0547.py` 实测 `sh600519`：

- `cursor=0` 返回 1 条基线，记录内 `updateTime` 作为游标；
- 下一次用**这个 updateTime** 作游标，返回 **0 条**（当前没有新成交）；
- 连续增量循环中，有新成交时返回 1 条并推进 updateTime，无新成交时返回 0 条；
- `silent` 段请求后静默 3 秒，收到 **0 字节**未请求数据；
- 自动分析：`INCREMENTAL_CURSOR_CONFIRMED`。

判定：`0x0547` 是**按代码游标的增量刷新**。客户端必须：

1. 首次传 0 建立基线；
2. 保存每条记录的 `updateTime`，下一轮作为该代码的游标；
3. 0 条响应时复用上一帧，不能当成行情失败或清空界面；
4. 每 60 秒强制一次 cursor=0 基线，防止未来游标/主站重启造成永久 0 条；
5. 记录数可能少于请求代码数，必须按记录内的「市场 + 代码」映射，不能按请求顺序硬配。

服务端协议还支持未配对的 `0x0547` 推送帧（msgId 与当前请求不匹配）；客户端已在
`TdxConnection` 中入队、由 `Bridge` 合并。当前免费主站实测 48 个配置主站各 5 秒、
75 秒单代码和 45 秒 80 代码均未主动下发帧；独立 eltdx 项目 2026-10-12 的
原生/池化/WebSocket 四层复验同样为 0 帧，但非零游标 refresh 正常
（[issue #21](https://github.com/electkismet/eltdx/issues/21)）。因此实时链路以
1 秒增量刷新为主；若收到推送帧则自动合并。

证据：

```text
~/.local/share/pythontdx/data/lake/probes/0x0547-20261102-103316.jsonl
~/.local/share/pythontdx/data/lake/probes/0x0547-analysis-20261102-103329.json
```

边界：主动推送是否发生由主站决定；本次未观察到，不宣称所有主站永不推送。

单条记录：

| 偏移 | 字段 |
| --- | --- |
| 0 | 市场 u8 |
| 1 | 代码 6s |
| 7 | active u16 |
| 9 | 五个差分 varint（同 `0x054c`） |
| — | 更新时间 u32 |
| — | 状态 varint、总手 varint、现手 varint |
| — | 成交额 u32（压缩浮点） |
| — | 内盘 / 外盘 / 外盘后未知 / 开盘金额（各 varint） |
| — | 五档：买价差 / 卖价差 / 买量 / 卖量（各 varint，循环 5 次） |
| — | 尾部保留区 |

首次刷新返回五档基线；后续调用才体现增量。当前实现的是**单次刷新**，
推送队列（主站主动下发、`msgId=0` 的未配对帧）尚未接入，见 `docs/09` P1。

### 3.9 分类行情 `0x054b`

请求 data 是 **9 个 u16**：

```text
category, sort_type, start, count, sort_reverse, 5, filter_raw, 1, 0
```

- `category=6` 是沪深 A 股；`sort_type` 常用 `0x000e`（涨幅）、`0x000a`（成交额）、
  `0x0006`（现价）；`sort_reverse=1` 降序、`2` 升序。
- 一页最多 80 条；`start` 翻页。服务端排序，不要本地重排。

响应：`u16 头 + u16 数量`（数量在 `[2:4]`），记录从偏移 4 开始**连续排列**，
单条由「9 字节头 + 变长字段 + 56 字节尾」组成。前段字段与 `0x053e` 类似：

| 偏移 | 字段 |
| --- | --- |
| 0 | 市场 u8 |
| 1 | 代码 6s |
| 7 | active1 u16 |
| 9 | 五个差分 varint：current / last_close / open / high / low |
| — | 时间 varint、负现价口径 varint |
| — | 总手 / 现手 varint |
| — | 成交额 u32（压缩浮点） |
| — | 内盘 / 外盘 / 外盘后 / 开盘金额（各 varint） |
| — | 买一价差 / 卖一价差 / 买一量 / 卖一量（各 varint） |
| — | 56 字节尾 |

56 字节尾里已确认的字段：

| 尾偏移 | 字段 |
| --- | --- |
| 0 | status/sort u16 |
| 2 | 涨速 i16（/100） |
| 4 | 短周期换手 i16（/100） |

| 10 | 开盘抢筹 i16（/100） |
| 22 | 量增速 f32 |
| 26 | 盘口深度 f32 |

价格与 `0x053e` 同口径：`raw / 100 / divisor`；`lockedAmount = 买一价 × 买一量 × 100`。
限价涨停时卖一为空是正常情况，不能当解析失败。

### 3.10 成交明细 `0x0fc5` / `0x0fc6`

当日用 `0x0fc5`，历史用 `0x0fc6`；单页上限 1800 条。

| 命令 | 请求 data |
| --- | --- |
| `0x0fc5` | `u8 市场 + u8 0 + 6s 代码 + u16 start + u16 count` |
| `0x0fc6` | `u32 YYYYMMDD + u16 市场 + 6s 代码 + u16 start + u16 count` |

响应：

- `0x0fc5`：`u16 数量 + 记录`（记录从偏移 2 开始）。

### 3.11 集合竞价 `0x056a`

请求固定 28 字节：

```text
u8 市场 + u8 0 + 6s 代码 + u32 日期 + u32 selector + u32 0 + u32 start + u32 limit
```

- 日期 `0` 表示当日；`YYYYMMDD` 表示历史（服务器只保留最近交易日，更早日期实测返回 0 点）。
- selector 默认 `0`：只返回 09:15–09:25 的开盘竞价；selector `1~7` 会返回全天快照，
  其中包含 **14:57–15:00 尾盘集合竞价**（实测 600519 为 213 点，末点 14:59:57）。
  UI「竞价」页签已加「早盘 / 尾盘 / 全天」切换。
- limit 默认 `500`，start 默认 `0`。

响应：`u16 数量 + 数量 × 16 字节`，每条记录：

| 偏移 | 字段 |
| --- | --- |
| 0 | 当日分钟 u16 |
| 2 | 价格 f32（已经是元，不再差分） |
| 6 | 虚拟匹配量 u32（手） |
| 10 | 未匹配量 i32（带符号；取绝对值 + 方向） |
| 14 | 保留 u8 |
| 15 | 秒 u8 |

时间 = `HH:MM:SS`。**虚拟匹配量不是已经发生的成交**，不能当逐笔成交额；
09:25 的过程快照也不能替代正式撮合。

fixture：`python/fixtures/auction-today.hex`（600519 2026-10-30，50 点）。
2026-10-31 实测：selector=0、日期 `0` / `2026-10-30` 均返回 147 点（09:15:02–09:24:58）；

### 3.15 九榜排行 `0x053f`（2026-11-04 新增）

一次请求拿 9 个榜单，替代「`0x054b` 每个榜单独翻页」。

- 请求 12 字节：`u8 category + u8 mode(默认 5) + 7s 保留(00 00 00 00 01 00 00) + u8 size`；
  `size` 是**每个榜单**的条数（1~255），默认 20。
- 响应：`u8 size` + 9 个榜单 × size × 15B，顺序固定：
  涨幅、跌幅、振幅、涨速、跌速、量比、正委比、负委比、换手。
- 每条 15B：`u8 市场 + 6s 代码 + f32 价 + f32 指标`；指标口径随榜单变化
  （涨幅榜是涨幅 %，量比榜是量比），不能统一当价格。

实现：`CMD_TOP_BOARD` / `top_board_data` / `parse_top_board` /
`Bridge.top_board`，归档 `lake/top_board/trade_date=.../c<category>_s<size>.jsonl.gz`。

实测（2026-11-04，8 个场内主站）：`category=0,size=5` 返回 9×5 条，
涨幅榜首条 `sh688507 169.57 / 18.888`。

### 3.16 主力监控 `0x0563`（2026-11-04 新增）

- 请求 10 字节：`u16 市场 + u32 start + u32 count`（count 默认 600，上限 600）。
- 响应：`u16 条数 + 每条 32B`：
  `market u16@0`、`code 6B@2`、未知 1B@8、`eventType u8@9`、未知 1B@10、
  `index u16@11`、未知 2B@13、`payload 13B@15`、`hour u8@29`、`minuteSec u16@30`。
- `payload`：首字节方向/子类型，其后 3 个 f32；19 类事件按 gotdx 文案映射
  （主力买卖、加速拉升/下跌、低位反弹、高位回落、撑杆跳高、平台跳水、单笔冲、
  区间放量/缩量、大单托盘/压盘/锁盘、竞价试买、涨跌停四子类、尾盘三类、
  盘中强弱势、急速拉升/下跌）。

实现：`CMD_UNUSUAL` / `unusual_data` / `parse_unusual` / `Bridge.unusual`，
归档 `lake/unusual`（按交易日）。实测 2026-11-04 沪市 09:15 竞价涨停事件
文案/价格/封单量均正确。响应 600 条约 19KB，接近 64KB 帧上限。

### 3.17 成交分布 `0x051a`（解析已实现，主站超时）

- 请求 10 字节：`u16 市场 + 6s 代码 + 2B 保留`。
- 响应：`u16 count + u8 市场 + 6s 代码 + u16 active`，随后一串**变长整数**
  （首字节 6 位数据 + 0x40 符号 + 0x80 续接）：
  基准价、昨收/开/高/低差值、服务器时间、特殊价、量、现量、`f32 成交额`、
  内盘/外盘、两个统计、3 组（买价差/卖价差/买量/卖量）、`u16 未知`，
  最后 `count` 条（价差/量/主买/主卖）。
- 分布档位的价差可能以 **32 位补码**返回（≥2^31 要回填 int32），否则价位会跳到天上。
- 价格统一 `/100`；成交量是变长整数原值，**不是** compact-float。

实现：`CMD_VOLUME_PROFILE` / `volume_profile_data` / `parse_volume_profile` /
`Bridge.volume_profile`，归档 `lake/volume_profile`（按代码）。

**实测结论**：2026-11-04 对 8 个场内主站 + 3 个券商主站
（180.153.18.170 / 202.108.253.139:80 / 117.34.114.13 / 119.29.19.242）
发 `0x051a` 全部 6~25s 超时，无节点响应。因此解析/归档代码保留并单测覆盖，
但不进入 `daily/watchlist/full` 预设，只在数据集中单独勾选；文档不宣称「已可用」。

## 五、MAC 0x12xx 协议（行情类，MAC 优先 + 7709 兜底）

MAC 与 7709共用 7709 端口，但请求帧是 `0x1c` 头（10 字节 + body）、响应 16 字节头，
命令字 `0x12xx`，是**另一套命令空间**，不是 7709 的新版本，也不是它的加密层。
三步握手后按 `u16 命令字 + 负载` 请求。

已实现（`python/tdx_mac.py` + `python/tdx_mac_ext.py`）：

| 命令 | 能力 | 说明 |
| --- | --- | --- |
| `0x120F` | 服务端信息 | `today` / `lastTradingDay` + 4 段交易时段；`market_status` 用它识别临时休市 |
| `0x1215` | 文件元信息 | 大小/状态/哈希；实测 `tdxfin/gpcw.txt` |
| `0x1217` | 文件分片下载 | 解析已实现；测试主机返回空分片，生产用 0x06b9 |
| `0x1218` | 资金流 | 今日/5 日主力、大单/中单，`mac_money_flow_batch` 12 路并发 |
| `0x122A` | 股票摘要 | 194B 定长：名称/昨收/开高低收/量额/量比/换手/均价 |
| `0x122B` | 批量报价 | 20B/160 位字段位图；价格已是元，量按手 |
| `0x122C` | 板块成分股报价 | 16B 位图 + 控制区；实测 881001 |
| `0x122D` | 单只快照 + 分时 | 35B 头 + 18B/点 + 汇总段 |
| `0x122E` | K 线 | 36B/条，首条作昨收基准；支持 start/count/adjust |
| `0x122F` | 分时成交 | 秒级（非 Level-2） |
| `0x1231` | 板块榜单 | 领涨股/涨幅 |
| `0x1237` | 市场监控 | 沪深异动合并 |
| `0x123D` | 集合竞价 | 16B/条，未撮合为 i32（负=卖方） |
| `0x123E` | 多日分时 | 最多 5 日，14B/点，按分钟回绕切日 |
| `0x124A` | K 线偏移 | total 大端 / returned 小端 |

A 股相关 15 条已全部实现；`0x254D/0x2562` 属 EX 通道，不做。

**不能全面替代 7709**：代码表、F10 文本、136B 财务、股本变迁、特殊涨跌停、退市日线、
九榜排行、服务器文件都只有 7709/0x06b9。数据源策略与实测见
[docs/19](19-MAC协议与数据源策略.md)。

离线同步支持 `--source auto|mac|7709`：`auto` 对 K 线/当日分时 MAC 优先，失败回退
7709；其余数据集走 7709/7615。

## 七、稳定性与边界

| 风险 | 对策 |
| --- | --- |
| 主站改名/下线 | 多主站 failover；列表集中在 `ENDPOINTS` |
| 握手方式变化 | 只发 0x000d；出现空包先检查这里 |
| 单次 80 只截断 | 按 80 分批；Python 与 TS 两侧都有常量 |
| 报文错位 | 每次请求独立超时，超时销毁连接重连 |
| 指数五档垃圾值 | 按代码规则识别指数，盘口置空 |
| 港股/美股/期货 | 不在范围（只做 A 股）；7727 也不接入 |
| 非官方协议 | 仅供学习；服务端随时可能改，商用需自行评估 ToS |
