### 2.1 三个行情命令别混用

资料（eltdx）对 `0x053e` / `0x0547` / `0x054c` 的边界说得很清楚：

| 命令 | 定位 | 请求 | 盘口 | 场景 |
| --- | --- | --- | --- | --- |
| `0x054c` | 当前基础快照 | 显式代码，无游标 | 买一/卖一稳定 | 初始化一批代码 |
| `0x0547` | 增量刷新 / 实时五档 | 最多 100 码 + 游标 | 首次五档，之后增量 | 实时订阅 |
| `0x053e` | 旧版完整快照 | 显式代码，无游标 | 五档 + 旧状态字段 | 兼容/对照 |

**结论**：实时 UI 已切到 `0x0547`（按代码增量刷新，首次游标 0 建立五档基线）；
`0x054c` 用于批量快照；`0x053e` 保留兼容与差分对照。2026-11-02 10:33 实测
`cursor=0` 返回 1 条，使用记录内 `updateTime` 再请求返回 0 条，已确认**增量游标语义**；
客户端缓存上一帧并推进游标。未配对推送帧已接入队列，但当前免费主站在 48 个配置主站
各 5 秒、75 秒单代码、45 秒 80 代码观察窗内未主动下发；不能据此宣称所有主站无推送。
独立 eltdx 项目在 2026-10-12 用原生 transport、单/池化 8-slot、WebSocket 网关四层复验，
同样 `poll_push` 0 帧，而同日非零游标 refresh 正常；结论是**真实免费 7709 主站不提供
可持续的主动推送，增量刷新可用**（[issue #21](https://github.com/electkismet/eltdx/issues/21)）。
三者解析器不能互换。
来源：[eltdx 7709-增量刷新推送队列](https://github.com/electkismet/eltdx/blob/main/docs/methods/7709-%E5%A2%9E%E9%87%8F%E5%88%B7%E6%96%B0%E6%8E%A8%E9%80%81%E9%98%9F%E5%88%97.md)
（协议 API 与 fixture；实际游标验证以本项目 10:33 探针为准）。

### 2.2 已确认的边界

- `0x052d` 只服务 OHLC 周期；历史资金流**不要**复用它（资料称 category 22 已被服务端废弃）。
- `0x0547` 单次最多 100 个代码，超过会静默截断到 100。
- 7709 的 F10 文本（`0x02cf`/`0x02d0`）与 7615 的 F10 是**两套独立数据源**。
- 指数五档是垃圾值（本项目已按代码规则置空）。
- 7709 不提供港股/美股；不要再从其他接口补。

## 三、主机与「最新 IP」

### 3.1 结论：主机表会变，必须测速而不是盲信静态 IP

社区列表（如 [pytdx `hosts.py`](https://github.com/rainx/pytdx/blob/master/pytdx/config/hosts.py)）
曾经很好用，但多年未更新，很多主机已下线；把它的 IP 直接写死会得到
「能 ping 通但拿不到行情」的假健康。

**最新主机表的优先级**：

1. **本机通达信客户端的 `connect.cfg`**：安装目录里有官方维护的主机表
   （资料称 `[HQHOST]` 约 48 台、`[DSHOST]` 16 台、`[HFHost]` 2 台），
   随客户端升级而更新，最接近「最新」。读取前先定位安装目录，读不到再降级。
2. **Windows 客户端公开主站列表（2026-10 核对）**：本项目内置 19 台，
   来源为 [rustdx `ip.rs`](https://github.com/jackluo2012/rustdx/blob/main/src/tcp/ip.rs)
   与 [eltdx 7709 文档](https://github.com/electkismet/eltdx/blob/main/src/eltdx/docs/COMMANDS_7709.md)；
   设置页 TCP 测速后选择，写入 `~/.local/share/pythontdx/data/server.json`，连接失败仍自动 failover。
   这是**社区维护的最新公开列表**，不等同于本机客户端私有 `connect.cfg`。
2. **带日期的种子列表**：包内附带，记录来源与抓取日期；每次发版可更新。
3. **用户覆盖**：环境变量 / 用户配置文件优先于包内种子；写坏要报错，不静默回退。
4. **不做远端自动拉取**：避免「远端把用户流量导向任意 IP」的供应链风险；
   更新种子走发版或用户手动更新。

### 3.2 探活：TCP 能连 ≠ 能用

资料（eltdx EXTENDED_MARKET）明确记录：免费主站对批量探测敏感，
短时间大量连接会触发限流，连基础命令都会被 RST，需要冷却约 2 分钟。
因此：

- 用**真实业务命令**探活（如代码数量/单只行情），不要只 `connect()`；
- 并发有上限，单实例只探一次；失败退避，禁止循环扫描；
- 记录 `host / port / 延迟 / 成功命令 / 时间 / 失败原因`，供排障；
- 探活结果只作**排序建议**，不把「一次成功」当永久健康。

### 3.3 本项目现状

`python/tdx_bridge.py` 里目前是 5 个硬编码入口：

```
124.71.187.122:7709
180.153.18.170:7709
116.205.183.150:7709
111.230.186.52:7709
119.97.185.59:7709
```

2026-10-30 实盘请求成功（未逐台测速）。这是**临时种子**，不是「最新列表」；
v0.7 要换成 `connect.cfg` + 探活 + 配置覆盖，见 `PLAN.md` 的 TD17/TD21。

### 3.4 安全与合规

- 只连公开行情主站，遵守限流；不做端口扫描、不暴力枚举。
- 不在日志/文档里记录用户公网 IP；主机表更新要可审计。

#### 5.3.1 本地竞价归档

`0x056a selector=0` 只保留最近交易日，因此在数据湖增加
`lake/auction/trade_date=YYYY-MM-DD/{code}.jsonl.gz + .manifest.json`：

- 规范化 JSONL 的 SHA256、行数、`parserVersion` 都写入 manifest；
- 读取时校验，损坏直接报错；
- 归档写入用原子替换，避免半个文件；
- 这是本项目对上游保留期的补齐，不是把服务器历史说成无限。
- 2026-10-31 实测 `sh688499` 66 点归档 + 回读通过；截图
  `auction-archive-save.png` / `auction-archive-read.png`。

## 十、研究记录

### 2026-10-30

- 确认 7709 仍是 2026 年可用的主通道；新命令 `0x0547/0x054c/0x054b` 已出现在
  社区实现中，但本项目尚未实现，不能声称支持。
- 确认 7615 是 F10/资料通道，和 7709 不是一套协议。
- 确认 7727/EX 主要服务非 A 股品种，按 G3 不做；MAC 走 7709，保留。
- 确认官方提供 `hsjday.zip` / `tdxfin.zip` / `tdxgp.zip` 三类离线包。
- 确认主机列表会漂移，社区 `hosts.py` 过时；采用 `connect.cfg` + 探针 + 配置覆盖。
- 确认本项目当前只实现 8 个 7709 命令，距离「A 股协议全覆盖」还有明显差距，
  已登记到 `PLAN.md` 的技术债与 v0.7 任务。

> 以后每次查资料，在本节追加日期与结论；不要覆盖旧记录。

### 2026-11-04

- 本地 clone `gotdx`（Go，185 个 go 文件）与 `eltdx`（Python + Rust）做源码级对照，
  产出 [docs/16](16-gotdx能力与推送机制调研.md) 与 [docs/17](17-eltdx协议差距与补齐清单.md)。
- **推送事实修正**：gotdx 的「推送」是 `client_subscribe_factory.go` 的「定时轮询
  + 快照 diff」，没有 0x0547 服务端主动下发；pythontdx 的 0x0547 增量游标反而更完整。
  本项目已在 `tdx_server` 落地进程内订阅 Hub（同 Key 合并轮询），不再让每个 SSE/WS
  连接各拉一次。
- **新命令实测**：`0x053f` 九榜排行、`0x0563` 主力监控在 8 个场内主站可用；
  `0x051a` 成交分布在 8 个场内 + 3 个券商主站全部 8s 超时，保留解析与手动数据集，
  不进入默认预设、不写「已支持」。
- **P0 修复**：0x054c 记录头校验、keyed 归档按 key 分片（11 类数据集）、
  全量翻页只认空页、本地 `.day` 按证券类型取系数并容忍残尾、0x0ffc 资金流落盘、
  0x0010 补 5 个股本字段。逐项证据与 fixture 见 docs/17 §8.1。
- **运行时**：帧长/解压上限、订阅 Hub 已实现；deadline/generation/retry-safe
  仍是待办（docs/17 §5）。
- 离线数据改为多进程 + 多线程 + 多服务器并行，交易日 08:45–15:45 禁止下载，
  见 [docs/18](18-离线数据并行同步.md)。
- **MAC 协议**：0x120F/1215/122A/122C/122D/122E/123D/123E/124A 实盘验证；MAC 不是 7709 超集，
  采用 MAC 优先 + 7709 兜底，见 [docs/19](19-MAC协议与数据源策略.md)。
- **历史专业财务 gpcw**：计算服务器 120.76.152.87 的 `tdxfin/gpcw.txt` + `tdxfin/gpcwYYYYMMDD.zip`；
  2026-09-30 实测 5,572 只 × 658 float，见 docs/03 §3.13.1。
- **7615**：三主机 failover、7 个缺失 Entry、HQServ 7 个页面、行业 20 个子页、
  84 个资讯频道，见 docs/03 §3.14.2。
