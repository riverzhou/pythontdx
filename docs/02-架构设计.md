## 一、总览：两个前端，一份数据实现

```text
┌────────────────────────────┐      ┌────────────────────────────┐
│ Electron 桌面              │      │ 浏览器 Web                  │
│ 主进程：窗口/托盘/更新     │      │ 静态页面 + 浏览器 API       │
│ preload：contextBridge     │      │ src/web/http-api            │
└─────────────┬──────────────┘      └─────────────┬──────────────┘
              │ JSON Lines（stdin/stdout）         │ HTTP / SSE / WebSocket
              ▼                                   ▼
     ┌────────────────────┐             ┌──────────────────────────┐
     │ Python sidecar      │             │ python/tdx_server.py     │
     │ python/tdx_bridge.py│◀────────────│ 复用同一个 Bridge         │
     └─────────┬──────────┘             └────────────┬─────────────┘
               │                                    │
               └────────────────┬───────────────────┘
                                ▼
                 ┌──────────────────────────────────┐
                 │ Bridge：协议 / 解析 / 编排 / 缓存 │
                 │ · 7709 / MAC / 7615 / 文件        │
                 │ · 实时行情、K 线增量、涨跌家数    │
                 │ · 数据湖 / 离线任务 / 落盘        │
                 └───────────────┬──────────────────┘
                                 │ TCP / HTTP
                                 ▼
                    通达信行情主站 / 计算服务器
```

三条硬约束：

1. **只有 Python 碰行情 IO**（socket、协议解析、文件、下载任务）；
2. **桌面与 Web 共用一套 `src/renderer`、`src/shared` 与设计令牌**；
3. **行情数据只有一份实现**：`Bridge` 的方法同时服务桌面 stdio 与 Web HTTP；
   TS 只做展示与传输，详见 A2/A8。

## 二、当前形态（v1.5）

### 2.1 桌面

```text
Renderer（SolidJS）
   │ window.api（preload 白名单）
   ▼
Electron main（Node）
   │ 转发命令 + 传输调度（QuotePoller / PushHub）+ 配置持久化
   ▼
Python sidecar（python/tdx_bridge.py，从打包后的 Nuitka 单文件启动）
   │ JSON Lines
   ▼
Bridge / TdxConnection → 7709 主站
```

- 主进程只保留：窗口/托盘/菜单/更新、拉起并守护 Python、IPC 转发、
  配置读写、传输队列/超时/退避；
- 行情合并、缓存、TTL、K 线增量、涨跌家数全部在 Python（1.5.0 起）；
- 渲染层只认 `window.api`，不知道数据来自 sidecar。

### 2.2 Web

```text
浏览器
   │ fetch / EventSource / WebSocket
   ▼
python/tdx_server.py（默认 127.0.0.1:8765，可 --web-dir out/web 单端口托管）
   │ 同一个 Bridge
   ▼
7709 / MAC / 7615 / 文件
```

- `/api/*` 是只读行情 + 数据工具 API；`/api/stream`（SSE）与 `/ws` 共享
  `SubscriptionHub`，同一组代码只轮询一次；
- Web 端 UI 状态（自选/设置/公式/持仓）写 `localStorage`；
- 行情数据不落浏览器缓存，统一由 Python 的 TTL/合并规则提供。

### 2.3 部署模式：桌面与 Web 二选一

Electron 与 Web 是**两种部署模式，不同时使用**：

| 模式 | 启动方式 | 数据通道 | 说明 |
| --- | --- | --- | --- |
| 桌面 | `npm run dev` / 安装包 | 主进程 ↔ stdio sidecar | 默认方式；窗口/托盘/更新可用 |
| Web | `python/tdx_server.py` + 浏览器 | HTTP / SSE / WebSocket | 适合本机浏览器或多设备只读访问（需自行加反向代理/鉴权） |

原则：

- 同一台机器只允许一个 Python 后端持有 7709 连接；
- 不设计「桌面 + Web 同时打开」的共享缓存、跨进程锁或双后端协调；
- 两种模式必须调用同一批 `Bridge` 方法（A2/A8），但部署上只选一种；
- 如果未来要做多端同时访问，应改成「桌面也连同一个 HTTP 后端」的单后端架构，
  而不是让两个进程各连一套。

### 2.4 两端共享

- `src/renderer`：同一套 SolidJS 组件、stores、图表；
- `src/shared`：类型、格式化、交易时段、图表几何、双端调度纯函数；
- `python/`：唯一数据实现；
- 差异只在 `src/main`（IPC/壳）与 `src/web`（HTTP/SSE/WS）两个适配层。

## 三、为什么是 Python 后端

| 问题 | 为什么不能放在渲染层/主进程 |
| --- | --- |
| 7709 是二进制 TCP | 浏览器开不了；Electron 渲染层也不该碰 |
| CORS | 浏览器不能直连行情主站 |
| 窗口节流 | 最小化时 Chromium 会节流定时器，推送节奏不能由界面决定 |
| 双前端 | 数据必须只有一份，否则桌面和 Web 会看到不同行情 |
| 长任务 | 补历史、下载、校验不能绑在某个窗口上 |
| 机器学习 | 原始报文、Parquet、DuckDB、特征生成都在 Python 生态里最顺 |

**反例**：在组件里 `setInterval(fetch(...))`；在主进程里再写一套 7709 轮询；
让每个浏览器标签页各连一次主站；在 Web 端自己合并 K 线/算涨跌家数。

## 四、契约：类型、传输与调用边界

### 4.1 共享类型

`src/shared/` 是三端（桌面渲染、Web 渲染、Python 契约）的单一事实来源：

```ts
export interface Quote {
  code: string
  price: number
  // ...
}
```

- `src/shared/**` 禁止 import `electron` / `node:*` / DOM API；
- Python 字段名/类型必须与 `shared` 对齐，由 fixture/单测锁住；
- 字段变更同时改：`shared` → Python 解析 → fixture → `docs/03`/`08`。

F10 纯文本解析同样在 `shared`（桌面/Web 共用、可单测），按职责拆成四层：

| 文件 | 职责 |
| --- | --- |
| `shared/f10.ts` | 稳定入口，只 re-export `parseF10` / `F10Block` |
| `shared/f10/model.ts` | 块类型、框线/折行/URL 正则、CJK 列宽 |
| `shared/f10/tables.ts` | 空格对齐表、无表头列表、数字列判定、单元格折行 |
| `shared/f10/links.ts` | 公告/报道 URL 归并、摘要表挂链、重复明细去除 |
| `shared/f10/parse.ts` | 主循环：框线表收集、标题/正文分层、分段表合并 |

### 4.2 两种传输

| 模式 | 桌面 | Web |
| --- | --- | --- |
| 请求-响应 | `ipcRenderer.invoke` → 主进程 → stdio `Bridge.send(cmd)` | `fetch` JSON → `tdx_server.py` → 同一个 `Bridge` |
| 服务端推送 | 主进程 `PushHub` 定时调用 Python，再 `webContents.send` | SSE `/api/stream` / WS `/ws`，由 Python `SubscriptionHub` 调度 |
| 壳能力 | 窗口/托盘/更新/对话框 | 不支持，明确降级 |

桌面仍保留 **shell IPC**：窗口控制、托盘、打开外链、文件对话框。这些是壳能力，
不是行情数据，不走 HTTP。

### 4.3 调用边界

```text
组件 ──▶ stores/ ──▶ lib/ipc.ts ──▶ 传输适配器（IPC / HTTP / WS）
```

- 组件不直接 `fetch`、不直接 `window.api`；
- `lib/ipc.ts` 同时承载壳能力与行情客户端；
- 传输适配器由入口注入 `baseUrl` / `wsUrl`，组件不区分桌面/Web。

### 4.4 HTTP API

`python/tdx_server.py` 用标准库 `ThreadingHTTPServer` 复用 `Bridge`：

| 能力 | 路径 |
| --- | --- |
| 健康检查 | `GET /api/ping` |
| 批量行情 | `POST /api/quotes` |
| 交易日历 | `POST /api/market_status`（TDX 节假日文件 + 0x120F） |
| 实时 K 线 | `POST /api/kline_live` |
| 分类行情/排行 | `POST /api/category` |
| 成交明细 | `POST /api/trades` |
| 集合竞价 | `POST /api/auctions` |
| 资金流 | `POST /api/money_flow` |
| F10 目录/正文 | `POST /api/f10_catalog` / `api/f10_content` |
| F10 在线页签 | `POST /api/f10_announcements` / `api/f10_profile` / `api/f10_valuation` / `api/f10_finance` / `api/f10_business` / `api/f10_shareholders` / `api/f10_reports` / `api/f10_news` / `api/f10_trading` / `api/f10_statement` |
| K 线/分时/五日 | `GET /api/kline` / `api/minute` / `api/five_day`（`fresh=1` 绕过 TTL） |
| 代码表 | `GET /api/code_list` |
| 涨跌家数 | `POST /api/market_breadth` |
| 财务统计摘要/导出/查询 | `POST /api/stats_summary` / `api/stats_export` / `api/stats_query` |
| 统计 CSV / Parquet / DuckDB | `POST /api/stats_csv` / `api/stats_parquet` / `api/duck_query` |
| 板块/行业 | `POST /api/blocks` / `api/industries` |
| 条件选股 | `POST /api/screen` |
| SSE 行情流 | `GET /api/stream?codes=…&interval=3000` |

- 默认绑定 `127.0.0.1:8765`，**无鉴权**，只能本机使用；
- 写接口校验 `Origin` 只允许本机页面；跨源写返回 403；
- 返回 `{ok, result}` / `{ok:false, error}`，带 CORS；
- WebSocket `/ws` 与 SSE 共用 `SubscriptionHub`，支持订阅/取消；
- Web 端优先 WebSocket，失败回退 SSE，`?transport=poll` 强制轮询。

Web 入口在 `src/web/main.tsx`：先 `window.api = createHttpApi()`，再动态导入
共享的 `src/renderer/src/main`；`vite.web.config.ts` 负责独立构建，产物 `out/web`。
桌面与 Web 共用 `src/renderer` / `src/shared`，差异只在外壳和传输适配器。

`tdx_server.py --web-dir out/web` 可把静态页与 API/SSE 放在同一端口：SPA 路由回退
`index.html`，资源带长缓存，路径穿越返回 403，支持 GET/HEAD。

## 五、一条行情数据的旅程

### 5.1 桌面

```text
① 主进程 QuotePoller 到点 → fetchQuotes
② TdxBridge.send('live_quotes') → Python
③ Bridge.live_quotes：
   0x054c 快照 → 0x0547 增量 → 合并 → 竞价兜底 → MAC 兜底
④ 结果经 JSON Lines 回到主进程 → webContents.send('quote:update')
⑤ stores/quotes 更新 → 细粒度 DOM 更新
```

### 5.2 Web

```text
① 浏览器订阅 /api/stream（或 /ws）
② Python SubscriptionHub 到点 → Bridge.live_quotes
③ 同一份合并结果扇出给所有订阅者
④ SSE/WS 帧 → stores/quotes → DOM
```

两条路的区别只有传输；第 ③ 步是同一份 Python 代码。

### 5.3 交易日历与休市

- **官方节假日文件**：仓库内置 TDX `Except<year>.zip` 的
  `neednote_RecentHSHoliday.txt` 快照（2025/2026），Python 与 TS 共用；
- **服务端当前状态**：MAC `0x120F` 返回 `today` 与 `lastTradingDay`，用于识别
  官方文件之外的临时休市；
- **接口**：`market_status` / `POST /api/market_status`；前端启动与每 5 分钟刷新，
  `marketSession` 支持 `holiday`（显示「节假日休市」）；
- **降级**：没有网络/缓存时退回工作日 + 官方节假日文件；未来未覆盖年份按工作日，
  不伪造交易日。

### 5.4 非交易时段

- Python 的 `_quote_interval()` 与 TS 的 `pollDelayMs()` 使用同一组规则：
  交易/竞价按用户间隔；午休/收盘放大 10 倍、最少 30 秒；
- 等待被下一次交易时段边界封顶（边界后 250ms 内恢复），避免低频定时器把开盘拖后；
- 窗口关闭/标签页关闭不影响 Python 的数据任务；桌面退出时 sidecar 一并关闭。

## 六、状态管理：谁持有什么

| 状态 | 存放位置 | 理由 |
| --- | --- | --- |
| 自选股、分组、主题、布局 | 渲染层 Store + 持久化 | UI 操作 0 延迟，落盘是副作用 |
| 行情快照 | Python 权威 + 渲染层最后一帧 | 双端一致；刷新节奏由数据层控制 |
| 分时 / K 线 / 涨跌家数缓存 | Python `Bridge` | 两端共用 TTL/合并/跨日规则 |
| 图表展示缓冲 | 渲染层（只读） | 只为绘制历史；不做缓存失效/指标计算 |
| 窗口尺寸/位置 | Electron 壳 | 属于窗口，不属于数据 |
| 主机健康/探活结果 | Python | 只对连接层有意义 |
| 原始报文/Parquet | 数据湖 | 长期积累、可重放 |

**写入策略**：前端改状态 → 立刻更新 UI → 异步提交壳/后端 → 防抖 + 原子写。
不允许「前端一套、后端一套」各自维护行情。

## 七、持久化

### 7.1 应用配置

```text
%APPDATA%/pythontdx/pythontdx.json
{
  "version": 2,
  "state": { "groups": [...], "settings": { ... }, "activeCode": "sh600519" },
  "window": { "x": 320, "y": 180, "width": 1280, "height": 820 }
}
```

- **原子写**：先写 `.tmp` 再 `rename`；
- **版本号 + 迁移**：读旧格式、写新格式；旧 userData/数据目录自动迁移，旧目录保留；
- **引用完整性**：`activeGroupId` 不存在时回落到第一个分组；
- Web 端 UI 状态写 `localStorage`（非行情数据，不保证多设备同步）。

### 7.2 数据湖

```text
data/
  raw/tdx/date=YYYY-MM-DD/...          # 原始报文/JSONL，zstd，只追加
  normalized/
    bars_1d/trade_date=YYYY-MM-DD/*.parquet
    bars_1m/trade_date=YYYY-MM-DD/*.parquet
    quotes/ticks/auctions/...
    fundamentals/...
  features/                            # 派生特征，记录版本
```

硬要求见 `docs/00` 与 `PRINCIPLES.md` D6：
原始层不可变、schema 有版本、point-in-time、保留退市证券、可重放。
本地数据默认永久保留，不提供清理/删除入口（D6.1）。

## 八、安全模型

| 措施 | 位置 | 作用 |
| --- | --- | --- |
| `contextIsolation: true` / `nodeIntegration: false` | Electron 壳 | 页面拿不到 Node |
| preload 白名单 | `src/preload` | 只暴露壳能力，不交 `ipcRenderer` |
| CSP | 渲染层 index.html | 限制脚本/连接来源 |
| 外链校验 | 壳 IPC | 只接受 http/https，交给系统浏览器 |
| 后端默认 `127.0.0.1` | Python 服务 | 不默认暴露公网 |
| Web 写接口 Origin 校验 | `tdx_server.py` | 防跨站覆盖本地数据 |
| Web 鉴权/TLS | 反向代理/服务 | 远程访问必须加，不能裸奔 |
| 主机表来源校验 | 后端 | 不自动拉远端列表，避免流量劫持 |
| 日志脱敏 | 后端 | 不记录用户公网 IP/凭据 |

## 九、目录约定（v1.5）

```text
src/main/        桌面壳：窗口、托盘、更新、配置、传输调度、IPC 转发
src/preload/     contextBridge 白名单
src/shared/      三端共享类型与纯函数（禁止平台 API）
src/renderer/    SolidJS 界面：components / stores / lib / styles
src/web/         Web 外壳与 HTTP/SSE/WS 适配
python/          协议 + sidecar + HTTP 服务 + 数据任务 + 数据湖
scripts/         图标、截图、Python 入口、协议探针
docs/            说明、协议、发布手册、边界与一致性
```

`src/shared` 的「禁止 import 运行时 API」是硬约束：
它同时被 Node 侧和 Web 侧的 tsconfig 编译，引入平台代码必然有一侧失败。

## 十、关键取舍（ADR 摘要）

| 决定 | 取舍 | 理由 |
| --- | --- | --- |
| 双前端共用渲染层 | 不为 Web 重写一套 | 行情软件的核心是数据与交互，不是两套壳 |
| Python 后端而不是 Node | 协议/数据生态在 Python | 7709、Parquet、DuckDB、Pandas/PyTorch 都顺 |
| 桌面保留 stdio sidecar | 不强制走 HTTP | 无端口冲突、启动简单；数据方法仍与 Web 共用 |
| Web 走 HTTP/SSE/WS | 多一层网络 | 浏览器必须能连；写操作只允许本机 |
| 数据缓存下沉 Python | TS 少一层缓存 | 两端同一 TTL/合并规则，避免漂移 |
| Parquet + DuckDB | 分析型读取更顺 | 列式压缩、按分区裁剪、直接给 ML |
| 不做 7727 / 港美股 | 少一大块非 A 股协议 | 与章程 G3 一致，避免范围失控 |
| 交易不下单 | 只做行情终端 | 券商通道/合规是另一条产品线 |

## 十一、已知边界与技术债

| 边界 | 影响 | 计划 |
| --- | --- | --- |
| 交易日历内置 2025/2026 | 2027 年需按 TDX 新 `Except2027.zip` 更新快照 | 每年 12 月更新 `python/fixtures/tdx_holidays.json` |
| 桌面/Web 调度实现各一处 | 只决定“何时调用”，数据规则仍在 Python | 保持薄壳；新增调度复用同一组测试向量 |
| Web 鉴权/TLS 未实现 | 只适合本机；远程需反向代理 | 部署文档中明确 |
| `f10 full` 全市场建库耗时以小时计 | 默认 core | 数据工具里按需开启 |
