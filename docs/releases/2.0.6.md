# pythontdx 2.0.6

**2026-11-18 · 自定义板块能移出个股、三张表能点表头排序、板块/概念补上涨跌色**

三条界面意见，背后是三处互不相干的老问题：删除按钮只在自选渲染过；排序只有排行榜的页签
和全市场那排按钮两条各写各的路径；`.tone-up` 只定义在排行榜行内。这一版把它们收成三份
共用实现，不动协议、缓存与数据湖。

## 修复

- **自定义板块的个股删不掉**：左栏「自定义」列表的 `StockRow` 一直没传 `onRemove`，
  悬停不出按钮，想移出一只只能把整个板块删掉。现在补上（按钮提示「移出板块」），
  并挡住一个坑：拿不到板块 id 时不能把 `undefined` 传给 `removeWatchItem`——
  那会退回「自选」分组，一点「移出」就把自选里的同一只删掉。
- **板块/概念没有彩色系统**：`.tone-up` / `.tone-down` 原来只在 `.ranking__row`、
  `.tape__price`、`.auction__row` 各定义一遍，于是同样的类名在全市场、板块/概念、
  板块左栏里全部静默失效，用户看到的就是「只有排行榜有彩色系统」。
  现在在 `styles/base.css` 一处全局定义（与 `.up/.down/.flat` 并列），
  并写成双类名 `.tone-up.tone-up` —— 它得压过组件里的中性色
  （如 `.block__item-pct { color: var(--text-3) }`），又低于 `.表 td:nth-child(n)` 这类列样式。

## 新增

- **三张表都能点表头排序**：新增 `lib/table-sort.ts`（`nextSort` / `compareSortValues` /
  `sortRows` / `quoteSortValue`）与 `components/atoms/SortHeader.tsx`，全市场 / 板块 / 排行榜
  共用一套状态机与视觉：未排序淡 `↕`、升序 `▲`、降序 `▼`，`aria-sort`，回车/空格也能点。
  两条硬约定：**缺值永远沉底**（不随升降序翻转，停牌股不会因为点了升序就霸占榜首）、
  文本按中文拼音序（不是 UTF-16 码点序）。
  可排序列：代码 / 名称 / 现价 / 涨跌幅 / 成交额 / 换手 / 量比 / 涨速。

## 变更

- **全市场列表去掉排序按钮行**：`涨幅 / 跌幅 / 成交额 …` 那排按钮与表头排序是同一个功能的
  两个入口，删掉按钮改由表头触发。数值列第一次点击仍要整表报价快照（按 400 只分批、
  进度可见，实测 5,618 只约 11 秒），之后换列 / 换方向**只在内存里重排**，不再请求。
  页脚显示「按涨跌幅降序 · 恢复默认顺序」。
- **排行榜的表头排序只重排当前页**：页签决定「哪一批股票」（服务端 0x054b / MAC），
  表头决定「这一批怎么排」，换页签会清掉本地排序。页脚写明「本地排序：涨幅升序
  （只重排当前 80 行）」，不把「涨幅前 80 里按成交额排」伪装成「成交额前 80」。
- **板块/概念**：成分股行情本来就整块取回（≤400 只），排序是纯本地重排，
  页脚给「恢复文件顺序」。

## 使用提示

- **全市场列表第一次点数值表头要等一下**：要把整表报价拉一遍（5,618 只约 11 秒，
  表格上方显示「MAC 拉全表报价并排序… 400/5618」）。拉完之后换列、换方向都只重排内存，
  不再等待；页脚会写「按涨跌幅降序」，点「恢复默认顺序」回到代码表顺序。
- **排行榜的表头排序只重排当前页**（前 80 或全市场前 300 行）：页签决定「取哪一批股票」，
  表头决定「这一批怎么排」，换页签会清掉本地排序。页脚写明
  「本地排序：涨幅升序（只重排当前 80 行）」，不把「涨幅前 80 里按成交额排」
  伪装成「成交额前 80」。
- **可排序列**：代码 / 名称 / 现价 / 涨跌幅 / 成交额 / 换手 / 量比 / 涨速。
  今开、最高、最低、昨收、成交量、均价、振幅、涨停、跌停、总市值、流通市值这些附加列
  暂不参与排序 —— 它们在不同数据源下不保证齐全（例如 0x054b 首屏不给市值），
  给半张表的字段加排序只会误导。
- 排序时表里显示的价格仍按当前页现取，**顺序来自点表头那一刻的全表快照**，
  所以数值的细微变动不会立刻改变次序；想让新价格重新定序，再点一次表头即可。
