# 01 · 快速开始

> 桌面端、Web 端、Python HTTP/WS 服务与三平台打包均已可用。
> 目标与范围见 `docs/00-项目章程.md`，进度见 `PLAN.md`。
> 三平台从零编译的完整步骤见 [README 快速编译手册](../README.md#快速编译手册)。

## 环境要求

| 项目    | 版本                    | 说明                                                                          |
| ------- | ----------------------- | ----------------------------------------------------------------------------- |
| Node.js | ≥ 20.19（实测 24.22.2） | 推荐 22 LTS 或更高。`node -v` 查看                                            |
| npm     | ≥ 10（实测 11.19.1）    | 随 Node 一起安装                                                              |
| Python  | ≥ 3.10（实测 3.14.10）  | **仅开发/打包需要**；运行行情桥接进程                                         |
| Nuitka  | 4.x（实测 4.3.4）       | `pip install -r requirements.txt`（含 duckdb/pyarrow/pandas/nuitka/patchelf） |
| Windows | Windows 10 22H2 x64     | 需要 VS 2022 Build Tools（C++）                                               |
| macOS   | macOS 27.2 arm64        | Apple Silicon；需要 Xcode Command Line Tools；不维护 Intel 版                 |
| Linux   | Ubuntu 26.04.1 x64      | 需要 build-essential / python3-dev / patchelf                                 |

> 不需要预装 Electron、Vite 或任何全局 CLI，所有 Node 工具都是项目内依赖。
> 打包后的 exe 自带 Python 桥接程序，**最终用户不需要安装 Python**。
> 三平台各自在对应系统原生构建，**不做交叉编译**。

## 安装与启动

```bash
npm install     # 安装依赖（首次会自动从 npmmirror 下载 Electron 二进制，约 235 MB）
npm run dev     # 启动开发模式
```

`npm run dev` 会做三件事：

1. 用 Vite 构建主进程与 preload 脚本到 `out/`；
2. 启动渲染层的开发服务器（默认 `http://localhost:5173`）；
3. 启动 Electron，主进程崩溃自动重启，渲染层改动热更新（HMR）。

## 只读 HTTP API

浏览器不能直连 7709，所以 Web 端先通过只读 HTTP API 取数：

```bash
python3 python/tdx_server.py --port 8765
curl http://127.0.0.1:8765/api/ping
curl -H 'Content-Type: application/json' \
  -d '{"codes":["sh600519"]}' http://127.0.0.1:8765/api/quotes
```

默认只绑 `127.0.0.1`，无鉴权，不要暴露到公网。已提供：
`/api/ping`、`/api/quotes`、`/api/category`、`/api/trades`、`/api/auctions`、
`/api/money_flow`、`/api/f10_catalog`、`/api/f10_content`、`/api/f10_announcements`、`/api/f10_profile`、`/api/f10_valuation`、`/api/f10_finance`、`/api/f10_business`、`/api/f10_shareholders`、`/api/f10_reports`、`/api/f10_news`、`/api/f10_trading`、`/api/f10_statement`、`/api/code_list`、
`/api/kline`、`/api/minute`、`/api/five_day`、`/api/stats_summary`、`/api/stats_export`、`/api/stats_query`、`/api/stats_csv`、`/api/stats_parquet`、`/api/duck_query`、`/api/blocks`、`/api/industries`、`/api/screen`。
Web 前端已接入，行情通过 `GET /api/stream?codes=...&interval=3000` 接收 SSE；行情 HTTP 只读，自选/设置等状态写 localStorage；
也支持 `/ws` WebSocket（订阅 `{"type":"subscribe","codes":[...],"intervalMs":3000}`），
前端优先 WebSocket，失败自动回退 SSE。

```bash
# 第二个终端：Web 前端（复用 src/renderer）
npm run dev:web          # http://localhost:5174，/api 代理到 8765
npm run build:web        # 产物 out/web

# 生产式单端口：静态页 + API + SSE 都在 8765
python3 python/tdx_server.py --port 8765 --web-dir out/web
# 打开 http://127.0.0.1:8765/
```

调试时可在 URL 加 `?transport=poll` 强制回退 3 秒轮询。
Web 搜索与桌面共用拼音索引（`gzmt` / `茅台` / `600519` 都能命中），
pinyin-pro 在首次搜索时懒加载。

## 打包与分发

产物统一放在 `release/<版本号>/` 下。

> 要**正式发一个版本**（递增版本号 → 更新 CHANGELOG → 打包 → 实测产物 → 打标签），
> 请照 [07-手动编译发布手册.md](07-手动编译发布手册.md) 走 ——
> 那里有每一步的判定标准、故障速查表与验收清单。

```powershell
npm run build:python            # Nuitka → python/dist/tdx-bridge.exe
npm run build                   # electron-vite → out/
npx electron-builder --win nsis dir
```

跑完会得到（`release/<版本号>/`；`win-unpacked` 重命名成带版本号的绿色目录）：

```
release/<版本号>/
├── pythontdx-<版本号>-setup.exe        ← NSIS 安装包（创建快捷方式 + 卸载项）
├── pythontdx-<版本号>-win-x64/         ← 散装绿色目录（整个目录拷到任意位置可运行）
├── pythontdx-<版本号>-win-x64.zip      ← 绿色包 zip（解压即用，76 个文件）
└── builder-debug.yml
```

### 两种产物怎么选

|          | 绿色包（目录 / zip）               | NSIS 安装包                |
| -------- | ---------------------------------- | -------------------------- |
| 安装     | 不需要，解压/拷贝即用              | 需要（可静默 `/S`）        |
| 数据位置 | `%APPDATA%\pythontdx\`（同安装版） | `%APPDATA%\pythontdx\`     |
| 卸载     | 删掉目录 + 上面的配置目录即可      | 走卸载程序（会清快捷方式） |
| 适用     | 免安装、放 U 盘、临时对比版本      | 日常使用、要开始菜单入口   |

> 绿色包**不是**单文件便携版：它没有 `PORTABLE_EXECUTABLE_DIR`，配置仍写
> `%APPDATA%\pythontdx\`。换电脑时把该目录一起带走即可恢复自选/设置。
> 需要「exe 旁边带数据」的单文件便携版，用 `npm run build:win:portable`。

### 国内网络下打包失败怎么办

打包需要从 GitHub Releases 下载 NSIS 工具链。项目的 `.npmrc` 已经配好镜像：

```ini
electron_builder_binaries_mirror=https://npmmirror.com/mirrors/electron-builder-binaries/
```

如果仍然失败，先删掉缓存再试：

```powershell
Remove-Item "$env:LOCALAPPDATA\electron-builder\Cache" -Recurse -Force
```

### 常见问题

- **杀毒软件报警**：未签名的 Electron 应用常被误报。代码签名需要购买证书，
  学习项目可以忽略，或在本机添加信任。
- **`%TEMP%` 里残留 `pythontdxPortable`**：正常退出会自动清理；
  如果应用被强杀（任务管理器结束进程）就会残留，手动删掉即可。
- **打包很慢**：第一次要下载工具链，之后走缓存，通常 1~2 分钟。

## 调试技巧

### 1. 渲染进程：F12 打开 DevTools

开发模式下 `F12` 或 `Ctrl+Shift+I` 打开 DevTools，可以看 DOM、改样式、断点调试 Solid 组件。

### 2. 渲染进程的日志会转发到终端

主进程注册了 `console-message` 监听，界面里的 `console.log / warn / error`
会带着 `[renderer:xxx]` 前缀打到运行 `npm run dev` 的终端里。
**白屏排查第一步就是看终端有没有红色输出。**

### 3. 主进程断点：VS Code

项目自带 `.vscode/launch.json`，在 VS Code 里选
**「Debug: Main + Renderer」** 然后按 F5：

- 主进程代码可以在 `src/main/**` 里直接下断点；
- 渲染层会用自带的 DevTools 打开，也可以在 `src/renderer/**` 下断点。

### 4. 看配置文件落在哪

开发模式启动后终端会打印一行：

```
[main] 配置文件：C:\Users\<你>\AppData\Roaming\pythontdx\pythontdx.json
```

删掉这个文件就等于「恢复出厂设置」（自选股会回到 6 只示例股票）。

### 5. 只想验证接口，不想开界面

见 [03-通达信行情手册.md](03-通达信行情手册.md) 末尾的 JSON Lines 调试片段。

### 6. 改完样式，如何确认「真的变好看了」

```powershell
npm run shot                              # 截图到 screenshots/app.png
node scripts/dev/screenshot.mjs out.png 8000  # 自定义路径与等待毫秒数
```

它会先用生产产物构建，再启动 Electron、等界面和数据加载完、截一张图就退出。
**这一步能抓到类型检查和单元测试都抓不到的问题**——比如布局溢出、
颜色不可读、图表画歪。项目里的分时图「昨收为 0」那个 bug 就是这么发现的。

**键盘 / 点击类交互怎么验收？** 静态截图拍不到按键，所以工具支持先把界面「操作」一遍：

```powershell
# 切到日K → 等档位出现 → 聚焦图表 → 缩到 80 根 → 按 ← 三次 → 回读档位与光标读数
$env:PYTHONTDX_CAPTURE_CLICK = '.segmented__item:nth-of-type(3)'
$env:PYTHONTDX_CAPTURE_FOCUS = '.chart-host'
$env:PYTHONTDX_CAPTURE_KEYS  = 'Up,Up,ArrowLeft,ArrowLeft,ArrowLeft'
$env:PYTHONTDX_CAPTURE_PROBE = '.chart-zoom'
$env:PYTHONTDX_CAPTURE_EVAL  = 'document.querySelector(".chart-tooltip")?.textContent'
node scripts/dev/screenshot.mjs screenshots/zoom.png 6000
```

| 环境变量                    | 作用                                                                            |
| --------------------------- | ------------------------------------------------------------------------------- |
| `PYTHONTDX_CAPTURE_CLICK`   | 依次点击的选择器（逗号分隔），用来切 tab 之类                                   |
| `PYTHONTDX_CAPTURE_FOCUS`   | 等界面就绪后聚焦的选择器（键盘事件需要有落点）                                  |
| `PYTHONTDX_CAPTURE_KEYS`    | 依次发送的按键，DOM 键名与 Electron 键名都收（`ArrowUp` = `Up`）                |
| `PYTHONTDX_CAPTURE_PROBE`   | 等它出现并把**文本打印到终端**，用于程序化断言                                  |
| `PYTHONTDX_CAPTURE_EVAL`    | 求值一个**只读**表达式并打印（量元素尺寸、数 SVG 节点、读浮层文字）             |
| `PYTHONTDX_CAPTURE_WHEEL`   | 注入滚轮，写法 `deltaY@选择器@横向比例`，比例可省（如 `-100@.chart-host@0.25`） |
| `PYTHONTDX_CAPTURE_POINTER` | 真实指针：`move@选择器@比例` / `click@选择器@比例`（会真的移动焦点）            |

顺序是「点击 → 等就绪 → 真实指针 → 聚焦 → 按键 → 滚轮 → 回读」，和人的操作一致。

> `CLICK` 与 `POINTER` 的区别值得记一笔：前者是 `element.click()`，
> **不会移动焦点**（焦点是 mousedown 的默认行为）。所以「点完 tab 之后焦点留在按钮上、
> 再按 ↑ 什么也不发生」这类问题，只有 `POINTER` 复现得出来（`docs/06` 第 26 条）。

> 按键名两种写法都收是有原因的：`sendInputEvent` 只认加速器键名，
> 传 DOM 键名时**不报错、也不生效**，静默失效过一次（`docs/06` 第 24 条）。
> 滚轮同理 —— 注入的 `deltaY` 与渲染层收到的**不是同一套单位**，
> 所以工具会自己换算，并在每次注入后把「请求值 vs 实收值」打出来自检（`docs/06` 第 25 条）。
> 第 22、23 条则记录了只有这样做才会暴露的真实缺陷。

## 常见问题

### `npm.ps1 cannot be loaded because running scripts is disabled`

Windows PowerShell 默认禁止执行脚本，而 npm 在 PowerShell 里会走 `npm.ps1`。三选一：

```powershell
# 方案 A：直接调用 npm.cmd（最省事，不影响系统设置）
npm.cmd install

# 方案 B：为当前用户放开本地脚本执行权限（推荐，一劳永逸）
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

# 方案 C：改用 CMD 或 Git Bash
```

### Electron 二进制下载失败 / 卡住

Electron 44 **没有 postinstall 脚本**，它是在第一次被 `require` 时惰性下载的。
项目根目录的 `.npmrc` 已经配置好国内镜像，正常情况无需干预：

```ini
electron_mirror=https://npmmirror.com/mirrors/electron/
electron_custom_dir={{ version }}
```

如果仍然失败，手动触发一次下载：

```powershell
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
$env:ELECTRON_CUSTOM_DIR = '{{ version }}'
node node_modules/electron/install.js
```

### 界面是白的，但终端没有任何报错

按顺序排查：

1. 终端里是否出现 `[renderer:error]` 或 `页面加载失败`；
2. F12 打开 DevTools，看 Console 与 Network；
3. 确认 `src/preload/index.d.ts` 里的 `Window.api` 声明与 `src/preload/index.ts` 的实际导出一致；
4. 检查 `out/preload/index.js` 是否被正确生成（`npm run build` 之后看这个文件在不在）。

### 行情不刷新

- 底部状态栏的指示灯：「实时」= 正常，「连接异常」= 看后面的错误文案；
- 非交易时段主进程会自动降频到 30 秒以上，这是**有意设计**，不是卡死；
- 窗口最小化时默认暂停请求（可在设置里关闭）。
